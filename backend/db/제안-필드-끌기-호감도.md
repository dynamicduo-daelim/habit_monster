# 제안: 필드 끌기 호감도를 서버에 저장하기 (DRAG)

2026-10-21 작성 (송윤서 작업, Claude 정리). 관련 결정: **D-20**(앱에 끌기 호감도 추가) · **D-46**(서버 모드에서는 일단 끔).
DB 스키마 · API 명세는 윤서가 직접 고친다 — 이 문서는 **고칠 때 무엇을 어디서 바꾸면 되는지** 적어 둔 체크리스트다.

## 지금 상태 (10-21)

| | 시연 모드 (서버 없음) | 서버 모드 |
| --- | --- | --- |
| 홈 필드에서 몬스터 끌어 옮기기 | 됨 | 됨 |
| 끌면 호감도 +1 (몬스터마다 하루 1번) | **됨** (`GameState.drag`) | **안 오름** — `HttpGameRepository.dragMonster`가 0을 돌려준다 |
| 이유 | — | 명세 v5 `POST /monsters/{id}/affection`의 `action`은 `PET` · `PLAY`뿐이고, DB `monster.affection_action.action_type` CHECK도 `('PET','PLAY')`뿐이라 저장할 곳이 없다. 저장 안 되는 호감도를 앱에서만 올리면 다시 켰을 때 줄어들어 헷갈려서 끔 (사용자 결정, D-46) |

## 바꿀 것

### 1. DB 스키마 (`docs/데이터베이스/schema.sql`, v1.7 → 다음 판)

```sql
-- monster.affection_action: 행동 종류에 DRAG 추가 (하루 1번은 기존 기본 키 (user_monster_id, action_date, action_type)가 그대로 막는다)
action_type TEXT NOT NULL CHECK (action_type IN ('PET','PLAY','DRAG')),
```

이미 만든 DB에 적용할 때 (마이그레이션 예시 — 제약 이름은 실제 DB에서 `\d monster.affection_action`으로 확인):

```sql
ALTER TABLE monster.affection_action DROP CONSTRAINT affection_action_action_type_check;
ALTER TABLE monster.affection_action ADD CONSTRAINT affection_action_action_type_check
  CHECK (action_type IN ('PET','PLAY','DRAG'));
```

### 2. DB 시드 (`docs/데이터베이스/seed.sql`)

```sql
('affection_drag_gain', '1', '필드에서 끌어 옮기기 (몬스터마다 하루 1회)'),
```
앱 값은 `Economy.dragAffectionGain = 1` (D-20).
`verify.sql`에 확인 쿼리를 더하려면: 설정 키 존재, `action_type` 값 집합.

### 3. API 명세 (`docs/api/습관몬스터_API명세_v5.md` → 다음 판)

- `POST /monsters/{id}/affection` 요청 `action`: `PET | PLAY | DRAG` (DRAG = 홈 필드에서 끌어 옮기기, 하루 1회 +1)
- 응답은 같은 모양 `{gain, affection, affectionTier}`. 오늘 이미 끌었으면 409 `ALREADY_DONE_TODAY`
  - 단, 앱은 끌기를 자주 한다 → **끌기만은 409 대신 200 `gain: 0`으로 줄지** 정해야 한다 (오류 토스트가 끌 때마다 뜨면 안 됨. 앱이 409를 조용히 무시해도 됨)
- `GET /monsters/{id}`의 `todayActions`에 `drag` 추가: `{pet, play, drag}`

### 4. 서버 코드 (DB · 명세가 바뀐 뒤)

| 파일 | 바꿀 것 |
| --- | --- |
| `config/BalanceConfig.java` | `REQUIRED`에 `affection_drag_gain`, `affectionDragGain()` 추가 (키가 없으면 서버가 안 뜨므로 시드와 같이) |
| `monster/MonsterService.affection` | `PET` · `PLAY` 검사에 `DRAG` 추가, 오른 양 = `affectionDragGain()`. 위 3번에서 "끌기는 200 gain 0"으로 정했으면 DRAG만 409 대신 그 응답 |
| `monster/MonsterService.monster` | `TodayActions`에 `drag` (`actions.contains("DRAG")`) |
| `monster/GrowthApiTest` | `다른_행동이면_400`의 DRAG를 정상 케이스로 바꾸고, 하루 1번 · 최대 호감도 테스트 추가 |

### 5. 앱 코드

| 파일 | 바꿀 것 |

| `core/state/http_game_repository.dart` `dragMonster` | 지금 `return 0` → `POST /monsters/{id}/affection {action: DRAG}`, 응답을 `GameState`에 (`draggedToday = true`, 호감도). 409면 조용히 0 |

## 하지 않기로 한 것
- 끌어 놓은 **위치**는 저장하지 않는다 (D-20 그대로 — 홈에 들어올 때마다 자리를 새로 잡는다).
