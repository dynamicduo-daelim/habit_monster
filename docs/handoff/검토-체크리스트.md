## A. 모든 단계에 공통 — 큰 그림 (⭐ 가장 먼저)

### A-1. 요청 하나가 지나가는 길 (이 그림을 말로 설명할 수 있으면 서버의 절반)
```
[앱 화면] → runGameAction → GameRepository ─┬─ LocalGameRepository → GameState 규칙   (서버 없이)
                                             └─ HttpGameRepository → ApiClient ──인터넷──┐
  ┌──────────────────────────────────────────────────────────────────────────────────────┘
  ▼  서버 /api/v1/…
  ① 토큰 검사(Spring Security)  ② UserGateFilter(탈퇴 · 온보딩)  ③ IdempotencyFilter(중복 방지 키)
  → 컨트롤러 → ④ 소유권 → ⑤ 업무 날짜 → ⑥ 값 형식 → ⑦ 규칙 → 서비스 → DB(PostgreSQL)
```
- 왜 이 순서인가: 명세 v5 "요청 검사 순서". 예) 23:59에 보낸 요청을 00:01에 같은 키로 재전송 → ③에서 첫 결과가 나가고 ⑤ 날짜 검사까지 가지 않는다
- 볼 곳: `backend/server/README.md` "요청이 지나가는 순서", `backend/CLAUDE.md`

### A-2. 용어 6개 (각각 한 문장으로 말할 수 있게)
| 용어 | 한 문장 |
| --- | --- |
| access / refresh 토큰 | 30분짜리 출입증 / 30일짜리 재발급권. refresh는 쓸 때마다 새것으로 바뀌고, 옛것이 다시 오면 도난으로 보고 전부 폐기 |
| 중복 방지 키 (Idempotency-Key) | 버튼마다 만든 번호표. 같은 번호표로 다시 오면 서버가 다시 처리하지 않고 첫 결과를 돌려줌 → 골드 두 번 빠짐 방지 |
| 트랜잭션 | 여러 DB 작업을 한 묶음으로 — 전부 성공하거나 전부 없던 일 |
| 업무 날짜 | 서울 00시 기준 "오늘". 휴대폰 시계가 아니라 서버가 정함 |
| 모듈 = 스키마 | DB를 `habit` · `wallet` · `monster` … 영역으로 나누고, 서버 코드도 같은 이름으로 나눠 각자 자기 영역만 씀 |
| GameRepository | 화면이 게임 상태를 바꾸는 유일한 창구. 뒤에서 앱이 계산할지 서버에 물을지 바꿔 끼움 |

### A-3. 🔍 어떤 단계든 결과를 받으면 이 순서로 검토
1. **계획 표를 먼저 받았나** — 만들/바꿀 파일 트리 + 무엇이 바뀌는지 (안 보여줬으면 요청)
2. **테스트 결과** — 서버는 H2 **와** 실제 PostgreSQL 둘 다, 앱은 `flutter analyze` + `flutter test` 개수. "통과했다"만 있고 개수가 없으면 물어보기
3. **문서** — `docs/작업-기록.md` 맨 위 일지(확인한 것 / 못 한 것 구분), 정한 게 있으면 `docs/결정-기록.md` D-번호, API가 생겼으면 `backend/README.md` 표
4. `git log --oneline -5`, `git diff --stat` — 바뀐 파일이 계획과 맞는지
5. **위험 신호** (보이면 멈추고 물어보기)
   - `docs/데이터베이스/*.sql`을 말없이 고침 (DB는 송윤서가 주인)
   - 새 의존성(build.gradle · pubspec.yaml)을 허락 없이 추가
   - 명세와 다르게 만들었는데 결정 기록이 없음
   - 서버 코드에 `LocalDate.now()` (→ `BusinessDates`를 써야 함), 수치 하드코딩 (→ `config.balance_config`)
   - 한 모듈이 다른 모듈의 테이블을 직접 INSERT/UPDATE
   - 화면이 `GameState`의 규칙 메서드를 직접 부름 (→ `GameRepository`로)
   - 묻지 않고 커밋 · 푸시

## B. 끝난 단계

### 0단계 — 서버 공통 기반 (`b58892f`)
⭐ 숙지
- **중복 방지 키가 어떻게 두 번 처리를 막는지** — 요청 전체를 트랜잭션 하나로 묶고, 키 행을 `FOR UPDATE NOWAIT`로 잠근다. 서버가 죽으면 DB가 잠금을 풀어 줌. 2xx는 결과를 같이 커밋, 4xx는 변경을 되돌리고 결과만 저장, 5xx는 저장 안 함 (결정 D-25 · D-27)
- **탈퇴했는데 access 토큰이 30분 살아 있는 문제**를 요청마다 사용자 상태를 DB에서 확인해 막은 것 (D-24)
- 토큰 "만료"와 "위조"를 다른 오류로 나눈 이유 — 앱이 만료면 재발급, 위조면 로그인 화면

## C. 남은 단계 — 시작 전에 정할 것 · 결과에서 볼 것

### 3-0 준비
- **정할 것 (Claude가 물어봄)**: ① 공식 SQL을 테스트에도 쓸지 (지금은 `docs/데이터베이스`에 git으로 올라가 있음 → A안이 자연스러움) ② Testcontainers(새 의존성) 도입 ③ 모듈 규칙 검사 도구(ArchUnit 등)
- 🔍 결과: 기존 테스트 25개가 **실제 PostgreSQL**에서 도는지 / `BalanceConfig`가 시드 키를 다 읽는지 / `WalletService`의 "같은 지급 두 번 → 한 번만", "동시 차감에도 음수 안 됨" 테스트
- ⭐ 숙지: 골드는 잔액 + **원장**(모든 증감 기록). `UNIQUE(사유, 참조 id)`로 중복 지급을 DB가 막음

### 3-1 온보딩
- **정할 것**: 시작 골드 50 · 성실볼 3개를 줄지 → 주려면 **DB에 설정 키와 원장 사유 추가 필요 (송윤서가 결정)**
- 🔍 결과: 온보딩 한 번에 생기는 행 목록(습관 · 기간 · 카테고리 · 목표 · 스타터 · 지갑…)이 **한 트랜잭션**인지 — 하나라도 틀리면 아무것도 안 남는 테스트가 있는지 / `PATCH /me/onboarding`이 지워졌는지 / 앱 `app.dart`가 서버 모드에서 `HttpGameRepository`를 쓰는지
- 🧪 처음으로 **에뮬레이터에서 서버 연동 확인** 가능한 단계 (가입 → 온보딩 → DB에 스타터가 생겼는지 `docker exec … psql`로 보기)

### 3-2 메인 조회
- **정할 것**: 상단 바 "DAY n"을 무엇으로 셀지
- 🔍 결과: 서버 모드 앱이 **샘플 데이터(DAY 12 · 연속 11일) 없이** 내 데이터로 시작하는지 / 남의 몬스터 조회 → 404

### 3-3 체크인 (가장 중요 · 규칙이 가장 많음)
- ⭐ 숙지: 점수 공식(0 ~ 25), 상위 3개 반영, 카테고리 레벨업, **기간 보너스 = 반영 점수 합 × (배수 − 1)**, 다시 체크해도 보상은 첫 제출 그대로(DB 트리거가 막음)
- 🔍 결과: **명세 예시 숫자가 테스트로 있는지** (53G · 레벨업 20G · 기간 보너스 280G · 성실도 88% · Lv.3 → 4) / 결정 B1(마지막 날 반영 안 돼도 보너스) · B3(선택지에 목표값 포함) 반영 / 같은 날 동시 제출 두 건 → 하나만
- **정할 것**: 수면(RANGE) 습관의 선택지 만드는 방식 (Claude가 보여 줌)

### 3-4 탐색 · 포획
- 🔍 결과: 꽝 / 가진 종(볼 없이 15G) / 안 가진 종 → 포획 · 도망 / 다시 탐색하면 이전 등장 SKIPPED / 처음 본 종 `newlySeen` / 5마리째 포획에서 해금권
- **정할 것**: 탐색 후보가 아예 없을 때(카테고리 Lv.1이면 스타터뿐) 어떻게 할지
- ⭐ 숙지: 확률이 들어간 규칙을 어떻게 테스트하는지 (랜덤을 고정해서 주입)

### 3-5 성장
- **정할 것**: 필드 끌기 호감도(D-20)를 서버로 옮길지 → **명세 · DB에 행동 종류 추가 필요 (송윤서)** / 쓰다듬기에 중복 방지 키를 둘지
- 🔍 결과: 구매 동시 두 건에도 골드 음수 안 됨 / 물약 진화 · 최대 레벨

### 4 나머지 화면
- 화면 흐름이 바뀌는 곳(기간 연장 · 도감 3단계 표시 · 통계)은 **기획서를 먼저 쓰고 송윤서 확인** (CLAUDE.md 원칙 ②) — 기획서 없이 화면부터 만들었으면 멈추기
- **정할 것**: 습관 최소 1개 규칙 유지 여부, 유료 목표 칸(MVP 밖) 처리
- 🔍 "목표 등록한 날 완료 불가"(C1) · 도감 SEEN이 앱 로컬 결과와 같은지

### 5 AI 대사 · 알림
- **정할 것**: LLM 서비스 · 모델 (시드는 `gemini`), API 키 발급(송윤서가 직접, 코드에 넣지 않음), 처음엔 로컬 알림으로 갈지
- ⭐ 숙지: **AI는 말만 하고 점수 · 골드에 영향 없음**, LLM 호출은 트랜잭션 밖 (잠금을 쥔 채 기다리지 않음), 3초 넘으면 템플릿

### 6 출시 준비
- 되돌리기 어려운 일(배포 · 스토어 · 결제)은 매번 확인받게 되어 있음 — 계정 생성 · 비밀번호 · 결제 입력은 송윤서가 직접
- 🔍 릴리스 키 해시를 카카오 · 구글 콘솔에 등록했는지 (지금은 디버그 키만)
