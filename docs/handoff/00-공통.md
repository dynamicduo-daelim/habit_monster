## 3. 반드시 지킬 작업 규칙 (저장소 `CLAUDE.md` 요약 + 사용자 요청)
- **바꾸기 전에 계획부터 보여준다**: 만들/바꿀 파일 트리, 무엇이 어떻게 바뀌는지 표 → 그 다음 구현. (사용자가 여러 번 요청함)
- **커밋 · 푸시는 사용자가 말했을 때만.**
- 졸업 발표용 — 사용자가 **설명할 수 있어야** 끝난다. 보고는 쉬운 말로: **한 일 → 확인한 것 / 못 한 것 → 내가 임의로 정한 것 → 사용자가 정해야 할 것.** 처음 나오는 용어는 한 줄로 풀어 쓴다.
- 새 패키지(의존성)는 이유를 먼저 말하고 허락받는다.
- 끝나면 문서 갱신 (커밋 전): `docs/작업-기록.md` 맨 위 일지 · 정한 것은 `docs/결정-기록.md`(D-32부터) · 구조가 바뀌면 `docs/프로젝트-이해.md` · `docs/진행현황-및-계획.md` 체크박스 · API가 생기면 `backend/README.md`.
- 한국어로 답한다. 결론부터.

### 서버 (`backend/server/src/main/java/kr/habitmonster/`)
| 패키지 · 파일 | 하는 일 · 쓰는 법 |
| --- | --- |
| `application.properties` | `server.servlet.context-path=/api/v1` → 컨트롤러는 `/auth/login`처럼 **`/api/v1` 없이** 매핑 |
| `common/ApiException` + `ErrorCode` | 오류는 `throw new ApiException(ErrorCode.X)` → `{code, message, errors?, provider?}` 응답. **새 오류 코드는 `ErrorCode`에 추가** (명세 "에러 코드 목록"의 코드 · HTTP 상태 그대로). 여러 필드 오류는 `new ApiException(code, msg, List<FieldError>)` |
| `common/BusinessDates` | 업무 날짜(서울 00시). `today()` · `weekStart()` · `monthStart()` · `requireToday(businessDate)`(다르면 409 `BUSINESS_DATE_CHANGED`). **`LocalDate.now()` 금지** |
| `idempotency/@Idempotent` | 컨트롤러 메서드에 붙이면 `Idempotency-Key` 헤더 필수 + 같은 키 재전송 시 첫 결과 재생 + 요청 전체가 트랜잭션 하나. 붙일 곳: 구매 · 간식 · 체크인 제출/수정 · 탐색 · 포획 · 목표 완료 · 카테고리 열기 + (결정 A3) 온보딩 · 습관 추가 · 목표 등록 · 기간 연장. 동작 원리: `IdempotencyFilter` 주석, 결정 D-25 · D-27 |
| `config/UserGateFilter` | 탈퇴 사용자 401, 온보딩 전 사용자는 `BEFORE_ONBOARDING` 경로만 허용 (403 `ONBOARDING_REQUIRED`) |
| `auth/WithdrawalStep` | 회원 탈퇴 때 각 모듈이 자기 데이터 정리. 새 모듈(습관 · 목표 · AI)은 이걸 구현하는 `@Component`를 둔다 (예: `idempotency/IdempotencyWithdrawal`) |
| `auth/` · `identity/` | 로그인 · 사용자 (1단계 완료). `@AuthenticationPrincipal Jwt jwt` → `Long.valueOf(jwt.getSubject())`가 user id |

**요청 검사 순서** (명세 공통 규칙): ① 토큰(Spring Security) → ② `UserGateFilter` → ③ `IdempotencyFilter` → 컨트롤러에서 ④ 소유권 → ⑤ 업무 날짜 → ⑥ 값 형식 → ⑦ 규칙.

## 6. DB 설계 원칙 (schema.sql 머리말 — 꼭 읽기)
- **모듈 = 스키마**(`identity` · `habit` · `goal` · `wallet` · `shop` · `monster` · `config` · `ai` · `api`). **각 모듈은 자기 스키마 테이블만 INSERT/UPDATE** → 서버 패키지도 모듈별로 나누고, 다른 모듈 데이터는 그 모듈 서비스를 호출해서 바꾼다. 한 요청 = DB 트랜잭션 하나.
- 사용자 단위 잠금 순서 고정 (교착 방지): `habit_user → goal_user → monster_user → inventory → wallet` (`SELECT … FOR NO KEY UPDATE`).
- 골드 · 볼 · 물약 차감은 조건부 UPDATE(`… WHERE balance >= ?`) 또는 위 잠금. `CHECK(>= 0)` 위반은 422로 바꾼다.
- 골드 증감은 `wallet.wallet` 잔액 + `wallet.wallet_ledger` 원장 한 줄 (`UNIQUE(reason_code, ref_id)`로 중복 지급 차단). 금액 0이면 원장에 쓰지 않는다.
- **수치는 `config.balance_config`에서 읽는다** (하드코딩 금지). 3-0에서 만드는 설정 읽기 도구를 쓴다.
- 행을 지우지 않는다 (상태값). 트리거가 막는 것: 보상 기준값 변경, 완료 목표 되돌리기, 끝난 탐색 결과 변경.
- JPA는 테이블을 만들지 않는다 (`ddl-auto=none`). 엔티티 컬럼은 `schema.sql`과 정확히 같아야 한다.

## 8. 함정 (실제로 겪은 것)
- **Windows PowerShell 5.1로 한글 파일을 고치지 말 것** (`Get-Content`/`Set-Content`가 UTF-8 한글을 깨뜨림). 파일 수정은 Edit/Write 도구나 python으로.
- Git Bash에서 `docker exec … /tmp/x` 같은 경로는 Windows 경로로 바뀐다 → `MSYS_NO_PATHCONV=1`.
- Docker Desktop은 `C:\Desktop\…`을 빈 폴더로 본다 (공유 범위 밖). D: 드라이브나 `C:\Users` 아래만.
- 포트: 5432 · 5433 · 5434는 이 PC의 다른 프로젝트 DB가 씀(5434 = treeplan) → 5435 (10-19에 5434에서 옮김). 8080은 treeplan 서버가 씀 → 이 프로젝트 서버는 8081 (`local` 프로필 기본값), 남의 프로세스는 끄지 않는다.
- PostgreSQL의 잠금 실패(55P03)는 Spring이 잠금 예외로 바꿔 주지 않는다 (`IdempotencyStore.isLockFailure` 참고). (서버 테스트는 실제 PostgreSQL에서만 돈다 — H2는 10-19에 지움, D-41)
- 실제 DB는 외래키가 있어 테스트 정리 순서가 중요 (자식 → 부모). `api.idempotency_record`는 사용자보다 먼저 지운다.
- `frontend/.metadata` · `pubspec.lock`의 도구 자동 변경은 커밋하지 않는다. `backend/.env`는 커밋 금지(.gitignore).
