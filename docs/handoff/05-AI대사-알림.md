# [5단계] 체크인 대사(AI) · 리마인드 알림

> 먼저 `00-공통.md`. 3-3(체크인)이 끝난 상태. 4단계와 병행 가능.
> **외부 서비스(LLM API 키 · Firebase)가 필요하다** — 키 발급 · 결제는 사용자가 직접 한다. 키를 코드 · 깃에 넣지 않는다 (환경변수).

## 5-1. 체크인 대사 `POST /checkins/today/dialogue` (명세 5장)
- 오늘 체크인의 **최신 revision당 한 번만** 만든다 → `ai.checkin_dialogue`(daily_checkin_id, revision) 저장, 같은 revision이면 저장된 걸 그대로
- LLM이 실패하거나 **3초(`llm_timeout_ms`)** 를 넘기면 템플릿 대사 → `source: "TEMPLATE"`
- 오늘 제출이 없으면 409 `CHECKIN_REQUIRED`
- DB 원칙 (schema.sql `ai` 머리말):
  - **AI는 말만 한다** — 점수 · 골드 · 보상에 영향 없음. `ai` 모듈은 경제 테이블에 접근하지 않고, 필요한 문맥(습관 이름 · 오늘 값 · 대화 상대 종 · 호감도 단계)은 **호출하는 쪽이 값으로 넘긴다**
  - **LLM 호출은 DB 트랜잭션 밖에서** (잠금을 쥔 채 네트워크를 기다리지 않음): ① 문맥 읽기(트랜잭션) → ② LLM 호출(밖) → ③ 저장(새 트랜잭션, 이미 있으면 그걸 반환)
  - 모델: `config.balance_config`의 `llm_model`(시드는 `"gemini"`) — 어떤 서비스 · 모델을 쓸지 **사용자에게 확인**. 키는 환경변수
- 서버 패키지 `ai/`, `WithdrawalStep` 구현(탈퇴 시 대사 · 대화 삭제)
- 앱: `features/chat/chat_brain.dart`의 `ChatBrain` 인터페이스로 `AiChatBrain` 구현 → 제출 응답 뒤 대사 API를 불러 말풍선에. 기다리는 동안 "…" (이미 지원). 실패해도 체크인 결과에는 영향 없음
- 테스트: LLM 클라이언트를 가짜로 바꿔 — 정상 · 3초 초과 → TEMPLATE · 같은 revision 재요청 → 같은 대사 · 다시 체크 후 → 새 대사 · 제출 전 409

## 5-2. 리마인드 알림 (기획서 9장)
- 하루 1회 **저녁 9시**, 그날 **접속(출석)하지 않은** 사용자에게: "당신의 재능에 대한 이야기를 궁금해하고 있어요"
- 서버: 스케줄러(`@Scheduled`, `Asia/Seoul`) → `habit.attendance`에 오늘 행이 없는 활성 사용자 → `identity.device_token`으로 FCM 발송. 여러 서버 인스턴스에서 중복 발송되지 않게(지금은 1대면 충분, 결정 기록에)
- 앱: Firebase 설정(`firebase_messaging` — 새 패키지, 이유 먼저) → 로그인 후 `PUT /me/device-token`, **로그아웃 때 `DELETE /me/device-token`**(이미 서버에 있음, 결정 A5). 알림 권한 요청 화면 흐름은 기획서로
- 대안(사용자에게 제안): 처음엔 앱 안 로컬 알림(`flutter_local_notifications`)으로 시작 — 서버 · Firebase 없이 됨. 다만 "접속 안 했을 때만"은 앱이 판단해야 함
- 테스트: 스케줄러 대상 선정 쿼리(출석한 사람 제외, 탈퇴 제외, 토큰 없는 사람 제외), FCM 클라이언트는 가짜로

## 완료 기준
