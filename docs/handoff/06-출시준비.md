# [6단계] 출시 준비 — 배포 · 보안 · 스토어

> 먼저 `00-공통.md`. 3 ~ 5단계가 끝난 상태.
> **배포 · 외부 전송 · 결제 · 스토어 등록은 되돌리기 어렵다 → 각 행동 전에 무엇을 할지 말하고 사용자 확인을 받는다** (CLAUDE.md 4장). 계정 생성 · 비밀번호 · 결제 정보 입력은 사용자가 직접.

## 할 일 (순서 제안)
1. **배포 대상 정하기** — 사용자와 상의: 클라우드(예: AWS · GCP · Render · Railway 등) + 관리형 PostgreSQL 16. 비용 · 학교 지원 크레딧 고려. 정해지면 결정 기록에
2. **DB**: 운영 DB에 공식 `schema.sql` → `seed.sql` 적용 (사용자가 직접 또는 함께). 이후 DB 변경은 마이그레이션 파일로 (도구 도입 여부는 사용자와 결정 — 예: Flyway)
3. **서버 설정**: 운영 환경변수 — `DB_URL` · `DB_USER` · `DB_PASSWORD` · `JWT_SECRET`(32자 이상 랜덤) · `KAKAO_APP_ID` · `GOOGLE_CLIENT_IDS` · LLM 키 · FCM 키. **HTTPS**. 로그에 비밀번호 · 토큰이 안 나오는지 확인
4. **보안 보강** (`docs/진행현황-및-계획.md` 6단계)
   - `/auth/login` 요청 횟수 제한 (같은 이메일 · IP 연속 실패)
   - 탈퇴 시 카카오 연결 끊기(unlink) — 카카오 정책 확인
   - 리프레시 토큰 재사용 감지의 유예 시간(30초)은 실제 문의가 있으면 (결정 C5)
   - 운영 빌드에서 HTTP(비암호화) 차단 (앱 디버그 빌드에만 허용돼 있음)
5. **앱 릴리스 빌드**
   - 릴리스 서명 키 생성(사용자가 보관) → **카카오 · 구글 콘솔에 릴리스 키 해시 / SHA-1 추가 등록** (지금은 디버그 키만 등록됨 — `docs/작업-기록.md` 4장 표)
   - `API_BASE_URL` = 운영 주소로 빌드
6. **스토어** — 개인정보처리방침 · 이용약관 (수집 항목: 이메일 · 소셜 ID · 습관 기록 · 푸시 토큰), 스토어 등록 정보 · 스크린샷 (`docs/발표` 캡처 참고). 등록 자체는 사용자가
7. **베타 튜닝** — `explore_miss_rate` · 탐색 가중치 · 보상 수치는 `config.balance_config`에서 조정 (코드 배포 없이). 변경 기록은 `schema_later.sql` B 블록(수치 변경 이력)을 쓸지 사용자와 결정

## 완료 기준
운영 서버에서 가입 → 온보딩 → 체크인 → 탐색까지 실제 폰으로 한 바퀴 + 체크리스트 문서(`docs/출시-체크리스트.md`, 새로)
