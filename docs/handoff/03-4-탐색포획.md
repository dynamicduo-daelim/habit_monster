# [3-4단계] 탐색 · 남은 등장 · 볼 던지기

> 먼저 `00-공통.md`. 3-3(체크인 → 탐색 기회 생성)이 끝난 상태. 명세 5장 "탐색하기" · "남은 등장 조회" · "볼 던지기"와 schema.sql `monster.explore_log` 주석을 읽고 시작.

## 범위
| API | 비고 |
| --- | --- |
| `POST /explores` | **`@Idempotent`**, `businessDate` 검사. 체크인 전 409 `CHECKIN_REQUIRED`, 남은 기회 0 → 422 `NO_EXPLORE_LEFT` |
| `GET /explores/pending` | 오늘 처리 안 한 `ENCOUNTER`(200) 또는 204. `newlySeen`은 false |
| `POST /explores/{exploreId}/capture` | **`@Idempotent`**, `businessDate` 검사. 남의 탐색 → **404**(C3), 닫힌 등장 409 `ENCOUNTER_CLOSED`, 볼 없음 422 `NO_BALL` |

## 규칙
**탐색 1회** (한 트랜잭션, `daily_explore_quota` 잠금 → `used_count + 1`, 조건부로 음수/초과 방지)
1. 남아 있는 처리 전 `ENCOUNTER`가 있으면 닫는다: 같은 날 → `SKIPPED`, 지난 날 → `EXPIRED` (응답 `skippedExploreId`)
2. 꽝 확률 `explore_miss_rate`(0.35) → `MISS`
3. 후보 = 오늘 `explore_quota_category`의 카테고리(= 연 카테고리 전부, B4) 종 중 `unlock_level ≤ 그 카테고리 레벨`
4. 가중치 = `explore_rarity_weight[희귀도]` × (안 가진 종이면 `explore_unowned_multiplier`). **"안 가진 종"에는 본 종(SEEN)도 포함** (명세 v5)
5. 가진 종 → `DUPLICATE`: 볼 없이 `duplicate_gold`(15) → 원장 `DUPLICATE`(ref `explore_log.id`), 끝
6. 안 가진 종 → `ENCOUNTER`(처리 전). **처음 보는 종이면 `newlySeen: true`** — 판단은 D-30: 그 사용자 `explore_log`에 그 종의 ENCOUNTER가 이전에 없었으면 처음
7. 후보가 아예 없으면? (예: 스타터만 있고 이미 가짐 → 전부 DUPLICATE가 됨) 명세에 없음 → 계획 때 사용자에게 보여 주고 정한다
8. 랜덤은 주입 가능하게 (`RandomGenerator` 빈 등) → 테스트에서 고정

**볼 던지기**
1. 볼 1개 소모: `shop.inventory` BALL 조건부 차감 + `shop.item_consumption`(consumer_key `CAPTURE:<idempotency-key>`) — 볼 0개면 422 `NO_BALL`
2. 포획률 `capture_rate[희귀도]` → 성공 `CAPTURED`: `user_monster` 생성(필드가 `field_max`면 가방), `dex_entry` 추가 / 실패 `ESCAPED`
3. `explore_log` 결과 기록 (한 번만 — 트리거가 다시 바꾸는 걸 막음, `consumption_id` 연결)
4. **도감 해금권**: 가진 종 수(`dex_entry` 수)가 `dex_unlock_thresholds`([5,10,15])에 닿으면 `habit.category_unlock_ticket` 지급 (UNIQUE(user_id, milestone)이 중복 막음) → 응답 `dex.newSlotAvailable`
5. 응답 `dex.dexCount` = 가진 종 수

모듈 경계: 탐색은 monster 모듈, 카테고리 레벨 · 해금권은 habit 모듈 서비스, 볼은 shop 모듈 서비스, 골드는 wallet. 잠금 순서: habit_user → monster_user → inventory → wallet.

## 앱 작업
- `HttpGameRepository.explore` · `throwBall`을 서버로. 응답 → `EncounterResult` · `CatchResult`(앱 `data/results.dart`). **앱 로컬 탐색 규칙은 monster-art-v2(D-19)에서 명세 v5에 맞춰 바뀌었다** (가진 종은 볼 없이 골드, 만나면 도감 등록). 지금 `EncounterResult` · `CatchResult` · `explore_view.dart`가 명세 응답(`result` MISS/DUPLICATE/ENCOUNTER, `outcome` CAPTURED/ESCAPED, `newlySeen`, `skippedExploreId`)을 담을 수 있는지 확인하고 모자란 필드만 더한다
- `exploreId`를 들고 있어야 던질 수 있음 → `EncounterResult`에 서버 id
- 챗봇 화면에 들어올 때 `GET /explores/pending`으로 남은 등장 복원
- 포획률 미리보기(`captureRate`), 도감 새 등록 연출(`newlySeen`)

## 테스트 (실제 DB, 랜덤 고정)
- MISS / DUPLICATE(골드 15, 볼 그대로) / ENCOUNTER → CAPTURED · ESCAPED
- 다시 탐색 → 이전 등장 SKIPPED, 날짜 지난 등장 EXPIRED, 닫힌 등장에 던지기 409
- 남은 기회 0 → 422, 볼 0 → 422, 같은 키 재전송, 같은 등장에 다른 키로 동시에 두 번 → 볼 하나만
- 해금권: 5마리째 포획에서 지급, 한 번만
- `newlySeen`: 처음만 true
- 체크인 전 409, 날짜 바뀜 409, 남의 탐색 404

## 완료 기준
위 테스트 + 앱 탐색 흐름이 서버로 동작 + 문서
