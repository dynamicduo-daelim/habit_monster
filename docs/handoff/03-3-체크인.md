# [3-3단계] 체크인 — 조회 · 첫 제출 · 다시 체크 (게임의 심장)

> 먼저 `00-공통.md`. 3-2까지 끝난 상태. 이 단계가 가장 규칙이 많다 — **명세 4-1 · 4-2 · 5장 "체크인" 세 절을 처음부터 끝까지 읽고** 시작한다.

## 범위
| API | 비고 |
| --- | --- |
| `GET /checkins/today` | 오늘 대상 습관을 카테고리 탭으로. `options`(B3) · `previousValue` · 대화 상대 |
| `POST /checkins/today` | 첫 제출. **`@Idempotent`**, 본문 `businessDate` → `BusinessDates.requireToday` |
| `PUT /checkins/today` | 다시 체크. **`@Idempotent`**, 보상 불변 |
| (대사 `POST /checkins/today/dialogue`는 5단계) | |

## 규칙 (명세 v5 + 구현 결정)
**점수 (4-1)** — 수치는 `BalanceConfig`(`score_target_hit` 20 · `score_max` 25 · `score_over_slope` 10 · `score_binary_done/miss`)
- TARGET_RATIO: 미달 `20 × 기록/목표`, 달성 20, 초과 `20 + 10 × (기록/목표 − 1)` 최대 25. **반올림 정수**
- BINARY(O/X): 했으면 20, 못했으면 0
- RANGE(수면, D-28): `목표 − range_below ≤ 기록 ≤ 목표 + range_above`면 20, 아니면 0 (`measure_type`)
- 달성률 = `min(점수 ÷ 20, 1) × 100` (반올림한 점수로), `overallRate` = 상위 3개 달성률 평균(반올림)

**첫 제출 (POST)** — 한 트랜잭션, 잠금 순서 지킴(`habit_user` 먼저)
1. 대상 = `ACTIVE`이고 현재 기간 시작일 ≤ 오늘인 습관 **전부**를 빠짐없이 보냈는지 (400), 본인 습관인지, `done:true`면 `value`가 그 습관의 `options` 중 하나
2. `done:false` → 값 0 · 점수 0
3. **반영 습관(`counted`)** = 점수 상위 3개 (`daily_counted_habits`), 동점은 등록 순서(습관 id)
4. **골드** = 반영 점수 합 (`gold_per_score`) → `WalletService.credit(CHECKIN, daily_checkin.id)`
5. **카테고리 경험치**: 반영 습관 점수가 그 카테고리 `user_category.exp_total`에. 레벨업 필요 = `category_exp_base × 현재 레벨`, 최대 `category_max_level`(20), 레벨업마다 `levelup_gold` → 원장 `LEVELUP`(ref `daily_checkin.id:카테고리코드`). 한 번에 여러 레벨 오를 수 있음
6. **종 해금**: 레벨업으로 새로 탐색 후보가 된 종 → `unlockedSpecies`
7. **채운 날 (B1)**: `done:true`(값 > 0)면 `is_filled` → 그 기간 `filled_days + 1` (**반영 여부와 상관없이**). 반영 습관이면 `counted_score_sum`에 점수 더함
8. **기간 보너스 (B1)**: `filled_days`가 `period_days`에 닿으면 `counted_score_sum × (배수 − 1)` 골드(`period_multiplier`) → 원장 `PERIOD_BONUS`(ref `habit_period.id`), 기간에 `ended_on` · `period_bonus`, 습관 `ENDED`. **그날 반영 습관이 아니어도 지급**
9. **탐색 기회**: `monster.daily_explore_quota` 생성 — 전부 "못했어"면 `explore_daily_all_missed`(1), 아니면 `explore_daily_free`(3). **`explore_quota_category`에는 연 카테고리 전부** (B4)
10. 행: `daily_checkin`(revision 1) · `checkin_submission`(키) · 습관마다 `habit_checkin`(rewarded_* · is_counted · is_filled · period_seq · target_snapshot)
11. 응답: 명세 예시 그대로 (`goldBreakdown` · `categoryExp` · `periodBonuses` · `exploreTotal` · `gold`). `categoryExp`의 필요 경험치 필드 이름은 `expRequired`(B2)

**다시 체크 (PUT)** — 대상은 **첫 제출에 들어간 습관 전체**(그 뒤 ENDED · STOPPED여도). 최신 `value` · `score` · `total_score` · `revision+1`만 바뀜. 보상 · 경험치 · 채운 날 · 탐색은 그대로 (DB 트리거가 막음 — 바꾸려 하면 트리거 오류가 난다). 오늘 제출이 없으면 404 `CHECKIN_NOT_FOUND`

**오류**: 날짜 다름 409 `BUSINESS_DATE_CHANGED` · 이미 제출 409 `ALREADY_SUBMITTED` · 대상 습관 없음 409 `NO_ACTIVE_HABIT`

## options 만들기 (B3)
목표 × {0.25, 0.5, 0.75, 1, 1.5, 2} → `step` 단위로 반올림 → 0 이하 · `max_value` 초과 제거 → 중복 제거 → **목표값이 없으면 넣기** → 오름차순. BINARY는 `[1]`. RANGE도 같은 방식(목표 주변 값)으로 하되 범위 안 · 밖이 둘 다 있게 — 정확한 방식은 계획 때 사용자에게 보여 주고 정한다.
**제출 검사도 같은 함수를 써서** "보여준 선택지 = 받는 값"이 되게.

## 앱 작업
- `HttpGameRepository.confirmCheckin` · `resubmitCheckin`을 서버로. 응답 → `DailyCheckinResult`(앱 `data/results.dart`)로 바꾸고 `GameState`에 반영 (골드 · 오늘 기록 · 반영 습관 · 탐색 횟수)
- 챗봇(`features/chat/chat_controller.dart`)의 선택지를 서버 `options`로 바꿀지 결정 (추천: 서버 모드에선 서버 값). 지금 앱은 `Catalog`/측정 항목으로 만든다
- 앱 `GameState.confirmCheckin`(로컬 규칙)과 서버 규칙 차이는 목록으로 보고만 (로컬은 서버 없는 모드용). 수면 범위: 앱 ±1 vs DB −1/+1.5
- 앱이 `businessDate`를 보내야 함 → `/me/status`의 `businessDate`를 `GameState`에 들고 있다가 사용

## 테스트 (실제 DB, 명세 예시를 그대로 테스트로)
- 명세 예시: 13 + 20 + 20 = 53G, 레벨업 20G, 기간 보너스 560 × 0.5 = 280G, `overallRate` 88, Lv.3(경험치 20) +13 → Lv.4(남은 3)
- 동점 → 등록 순서, 4~5개 중 상위 3만 반영, 전부 "못했어" → 탐색 1
- 마지막 날 반영 안 된 습관도 기간 보너스(B1), ENDED가 됨
- 다시 체크: 값 · 점수만 바뀌고 골드 · 레벨 그대로, 404, 같은 키 재전송 → 같은 응답
- 날짜 바뀜 409, 이미 제출 409, 빠진 습관 400, 선택지 밖 값 400, 같은 날 동시 제출 두 건 → 하나만
- RANGE 점수 경계값
