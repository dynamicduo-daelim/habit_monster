# 도감 · 카테고리 열기 서버 연결 (4-3)

- 날짜: 2026-10-28
- 상태: 구현 완료 (10-28)
- 관련: `feature/backend-game-system` · 명세 v5 7장 · D-17(만나면 등록) · D-30(본 종 = 탐색 등장 기록) · D1 · D6(`imageKey`)

## 1. 왜 만드나
- **문제**: 서버 모드에서 도감의 "본 종"은 앱을 다시 켜면 사라진다. 카테고리 열기도 앱 안에서만 바뀌어 저장되지 않는다.
- **목표**: 도감(가진 종 · 본 종 · 모르는 종)과 카테고리 열기를 서버 기준으로.
- **하지 않는 것**: 도감 화면 모양 바꾸기 (본 종 · 실루엣은 10-15에 이미 있음), 카테고리 레벨 조회 (명세에 없음, D-43 그대로).

## 2. 사용 흐름
1. 도감 탭 → 서버 데이터로 가진 종 · 본 종 · 실루엣이 보인다 (지금 화면 그대로).
2. 가진 종이 5 · 10 · 15마리가 되면 해금권 1장 → "새 카테고리 열기" → 카테고리 고르기 → 열림 + 시작 몬스터.

## 3. 규칙
서버 (명세 7장 그대로):
- `GET /dex`: 가진 종 수 · 다음 기준 · 남은 해금권, 카테고리마다 가진 · 본 · 전체 종 수.
- `GET /dex/categories/{code}`: 종마다 `OWNED`(이름 · 레벨) / `SEEN`(이름) / `UNKNOWN`(그림 이름 `imageKey`와 출현 레벨만 — 이름 · 번호 없음, D6).
- `GET /dex/species/{id}`: 본 적 없는 종은 404 `NOT_DISCOVERED`.
- `POST /categories/{code}/unlock`: 중복 방지 키 필수. 해금권 없음 422 `NO_TICKET`, 이미 연 카테고리 409 `ALREADY_OPENED`. 연 카테고리는 Lv.1, 시작 몬스터는 필드가 5마리면 가방으로.
- 본 종 = 탐색에서 그 종이 등장한 기록이 있음 (D-30, DB 변경 없음). 가진 종 수만 해금권 기준에 들어간다.

앱:
- 서버 모드는 도감 데이터를 서버 값으로 채우고, 카테고리 열기는 서버를 부른다. 시연 모드는 지금 그대로.
- 열 수 있는지는 서버의 남은 해금권(`availableTickets`)으로 판단한다.

## 4. 화면
- 바뀌는 모양 없음. 데이터 출처만 서버로. → 캡처는 확인용으로만 찍고 남기지 않는다 **[가정]**.

## 5. 예외
- 해금권이 없는데 열기 → 서버 422 문구 토스트 (앱은 버튼을 숨기므로 보통 안 생김).
- 앱이 켜진 채 다른 기기에서 열었으면 409 → 토스트 후 다시 불러오기 **[가정]**.

## 6. 영향
- 서버: `monster/`(또는 조율 서비스 `dex/`) API 4개, 오류 코드 3개(`NOT_DISCOVERED` · `NO_TICKET` · `ALREADY_OPENED`), `DexApiTest`.
- 앱: `HttpGameRepository.load`(도감) · `openCategory`, `GameState.apply…`, 테스트.

## 9. 결과 (구현 뒤에 쓴다)
- 기획과 달라진 점
  - 서버 모드의 카테고리 칸이 "연 카테고리 + 안 쓴 해금권"이 됐다. 시연 모드처럼 기본 3칸이 아니어서, 온보딩에서 1 ~ 2개만 고른 사람은 해금권(가진 종 5마리)이 생길 때까지 새 길을 못 연다 (명세 · DB 규칙 그대로, 기획 변경 이력에 기록).
  - 시작 몬스터로 가진 종이 5 · 10 · 15에 닿으면 해금권을 또 준다 (포획과 같은 규칙, D-49).
- 확인한 것: 서버 테스트 **147개 통과** (새 `DexApiTest` 8개 — 세 상태 · 모르는 종 숨김 · 상세 404 · 남의 도감 · 열기 · 가방 · 해금권 추가 · 같은 키). 앱 `flutter analyze` 이상 없음, 테스트 **128개 통과** (새 3개).
- 확인하지 못한 것: 실제 서버(8081)에 요청, 폰 · 웹에서 눌러 보기. 화면 모양은 바뀌지 않아 캡처는 찍지 않았다.
