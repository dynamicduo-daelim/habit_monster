# 체크인 대사(AI) · 21시 리마인드 알림 (5단계)

- 날짜: 2026-11-08
- 상태: 5-1 서버 **구현함**(2026-11-09, 테스트 실행 전) · 앱 연결은 프론트 담당 / 5-2 앱 로컬 알림 — 프론트 담당
- 관련: 명세 v6 5장 `POST /checkins/today/dialogue`, 스키마 `ai.checkin_dialogue`(v1.7), 기획서 `2026-10-29-AI-챗봇-체크인.md` 6번 "반응 대사", D-57(AI는 말만), D-64, `frontend/서버연동-메모.md` 5장

## 1. 왜 만드나
- **문제**: 체크인을 확정하면 몬스터가 늘 같은 대본 대사를 한다 (`ScriptedChatBrain.wrapUp`). 그리고 앱을 안 연 날에는 체크인을 잊는다.
- **목표**
  - 5-1: 확정한 오늘 기록을 보고 몬스터가 그날에 맞는 한마디를 한다 ("30분이나 뛰었구나!").
  - 5-2: 그날 앱을 안 연 사람에게 저녁 9시에 한 번 알림.
- **하지 않는 것**
  - FCM(서버 푸시) — 로컬 알림만 (사용자 11-08, D-64)
  - 대사가 점수 · 골드 · 보상을 말하거나 바꾸는 것 (D-57)
  - 대화 원문 저장 (해석 API와 같음)

## 2. 누가 · 언제 쓰나
- 5-1: 매일 체크인하는 사람. 챗봇에서 [맞아]로 확정(제출)하거나 다시 체크를 저장한 직후.
  1. 앱이 `POST /checkins/today` (또는 `PUT`) → 결과(점수 · 골드)를 받는다
  2. 앱이 바로 `POST /checkins/today/dialogue` → 기다리는 동안 말풍선 "…"
  3. 대사가 오면 말풍선에. 실패해도 결과 화면은 그대로
- 5-2: 하루 동안 앱을 열지 않은 사람. 저녁 9시에 폰 알림 → 누르면 앱이 열린다.

## 3. 규칙

### 5-1 체크인 대사 (서버)
- 오늘 체크인의 **최신 revision당 한 번만** 만든다. 같은 revision이면 저장된 대사를 그대로 돌려준다 (모델을 다시 부르지 않음).
- 다시 체크하면 revision이 올라가서 새 대사를 만든다.
- 오늘 제출 전이면 409 `CHECKIN_REQUIRED`.
- 모델에 주는 것: 대화 상대 몬스터 이름 · 호감도 단계(말투), 오늘 습관별 이름 · 카테고리 · 한 값(못 했으면 "못 함") · 목표 · 단위, 다시 체크인지. **점수 · 골드는 주지 않는다.**
- 서버가 다시 검사한다 (모델을 믿지 않음):

| 검사 | 걸리면 |
| --- | --- |
| 3초(`app.llm.timeout-ms`)를 넘기거나 실패 · 형식 오류 | 템플릿 대사 |
| 대사에 **기록(한 값 · 목표)에 없는 숫자** | 템플릿 대사 (지어낸 점수 · 골드 · 연속 일수 막기) |
| 빈 대사 | 템플릿 대사 |
| 120자 넘음 | 자름 |

- 템플릿 대사 ("했어"인 습관 수로):

| 경우 | 대사 |
| --- | --- |
| 전부 했어 | 오늘 습관을 전부 해냈구나! 정말 멋져. |
| 일부 | 오늘도 해낸 게 있어서 좋아. 내일도 같이 하자! |
| 전부 못 했어 | 괜찮아, 그런 날도 있어. 내일 다시 같이 해 보자. |

- 순서: ① 문맥 읽기(짧은 트랜잭션) → ② 모델 호출(**트랜잭션 밖**) → ③ 저장(새 트랜잭션, 같은 revision이 동시에 오면 먼저 저장된 것을 돌려줌).
- 탈퇴하면 그 사람의 대사 · 하루 AI 호출 수를 지운다.
- **[가정 → Claude가 정함]** 대사 호출은 하루 AI 한도(60회)에 세지 않는다 — revision마다 한 번이라 하루 몇 번으로 끝난다 (D-64).
- **[가정 → Claude가 정함]** 위기 키워드 검사는 하지 않는다 — 대사에는 사용자가 쓴 말이 없다 (위기 신호는 해석 단계에서 이미 본다).

### 5-2 21시 리마인드 (앱 로컬 알림)
- 그날 앱을 열지 않았으면 저녁 9시(폰 시간)에 한 번: **"당신의 재능에 대한 이야기를 궁금해하고 있어요"** (기획서 9장 문구).
- 앱이 판단한다 — 서버 · Firebase 없음.
- **[가정]** 방법: 앱을 열 때마다 "오늘 이후 7일치 21시 알림"을 다시 예약하되, 오늘은 이미 열었으니 **내일부터**. 7일 넘게 안 열면 알림도 멈춘다 (계속 울리면 오히려 지우게 됨).
- **[가정]** "열었다" = 출석 기준과 같음 (`2026-10-10-출석-접속-기준.md` — 앱을 열어 홈에 들어옴).
- 알림 권한: 안드로이드 13 이상은 권한 요청이 필요하다. 언제 물을지(온보딩 끝 / 첫 체크인 뒤)는 프론트 담당이 사용자와 정한다.
- 설정에서 끄기 — 있으면 좋음 (프론트 담당 판단).

## 4. 화면
- 5-1: 새 화면 없음. 챗봇 확정 뒤 몬스터 말풍선 (`ChatBrain.wrapUp` · `recheckDone` 자리). 기다리는 동안 "…"는 이미 있다.
- 5-2: 폰 알림 하나. 앱 안 화면은 권한 요청 안내 정도.

## 5. 예외 · 경계
- 대화 상대 몬스터가 없음 → 이름 "루틴몬", 보통 말투
- 대사 요청이 늦게 도착(3초 이상) → 앱은 기다리다 템플릿으로 바꿔도 됨. 서버가 저장한 대사는 다음 요청에 그대로
- 다시 체크 직후 예전 revision의 대사 요청이 겹침 → 그 요청 시점의 최신 revision 기준
- 하루가 바뀜 → 어제 체크인의 대사는 요청할 수 없음 (오늘 기준)
- 폰 시간대가 한국이 아님 → 5-2는 폰 시간 21시 (한국 사용자 기준이라 문제 적음)
