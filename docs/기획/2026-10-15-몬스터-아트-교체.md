# 몬스터 아트 교체 (5종 → 28종, 진화 그림 4종)

- 날짜: 2026-10-15
- 상태: 구현 완료. 사용자는 "몬스터 다 교체"까지만 정했고, 이름 · 희귀도 · 출현 레벨 · 첫 파트너는 Claude가 정했다(**[가정]**). 8번에서 확인받는다.
- 관련: 브랜치 `feature/habit-manage` (커밋 전), 결정 D-16

## 1. 왜 만드나
- **문제**: 교수님 피드백 — 몬스터 그림이 포켓몬과 너무 닮았다 ("포켓몬 냄새가 많이 난다").
- **목표**: 게임 구조(속성 카테고리 · 탐색 · 성실볼 · 도감 · 진화)는 그대로 두고 **그림만** 우리 것으로 바꾼다. 픽셀 아트는 유지한다.
- **하지 않는 것**: 규칙 · 수치 변경, 2차 진화(Lv.20) 그림, 대사 시스템 변경.

## 2. 누가 · 언제 쓰나
- 모든 사용자. 온보딩(첫 파트너 고르기), 홈 필드, 교감 창, 챗봇, 탐색, 도감, 가방에서 보인다.
- 그림 출처: 사용자가 AI로 뽑은 픽셀 그림 32장 (`속성_동물N.png`). 이름 끝 `2` = 진화 그림 (사용자 확인).

## 3. 규칙
- 카테고리마다 4~6종. 도감 칸(카테고리당 7칸, 10-15 API 명세 v4에 맞춰 6 → 7)을 넘지 않는다.
- 카테고리마다 첫 파트너 1종(흔함 · 출현 Lv.1). **명상 · 절약에도 이제 첫 파트너가 있다** (전에는 그림이 없어 없었다).
- 진화 그림이 있는 종은 **Lv.10(1차 진화)부터** 진화 그림으로 보인다. Lv.20(최종형)은 그림이 따로 없어 진화 그림 그대로.
- 진화 그림은 "내가 가진 몬스터"에만 쓴다 (홈 필드 · 교감 창 · 가방 · 챗봇 · 튜토리얼). 도감 · 탐색은 종의 기본 그림.
- 희귀도: 앞쪽 두 종 흔함 → 가운데 보통 → 마지막 종 희귀. **[가정]**
- 출현 레벨 (10-15 바꿈, API 명세 v4 · D-19): 카테고리 안에서 **1 · 3 · 6 · 9 · 12 · 15 · 18** 순서. 명세의 "카테고리 7종 기준" 표를 앞에서부터 종 수만큼 쓴다. 카테고리 레벨은 최대 20.

카테고리 레벨 곡선(10 × N점)으로 보면 Lv.3 = 30점, Lv.6 = 150점, Lv.9 = 360점, Lv.12 = 660점, Lv.15 = 1,050점, Lv.20 = 1,900점. 습관 하나가 하루 최대 25점이라 한 카테고리에 습관 하나면 Lv.3까지 2일쯤, Lv.9까지 15일쯤 **[가정 — 계산만 함, 실제 플레이로 확인 안 함]**.
- **빈 칸**: 도감은 카테고리마다 7칸이다 (명세가 7종 기준). 종이 4~6종이라 남는 칸은 "준비 중"으로 보인다 (모두 14칸: 운동 2 · 공부 3 · 식습관 2 · 명상 3 · 수면 3 · 절약 1). 그림을 더 뽑으면 채워진다.

## 4. 화면
- 그림 파일: `frontend/assets/images/monsters/<영문 id>.png`, 진화 그림은 `<id>_2.png`. 원본을 투명 여백 없이 자르고 긴 변 384px로 줄였다 (전 그림과 같은 크기).
- 온보딩 인트로의 실루엣 4마리: 원숭이 · 쥐 · 거북 · 다람쥐.
- 홈 필드 높이(`fieldHeight`)는 몸 모양에 맞춰 58~76px (납작한 가오리 · 박쥐 · 우파루파는 낮게).

## 5. 예외 · 경계
- 예전 종 id(`wolf` 제외)로 저장된 데이터는 없다 (앱이 아직 저장하지 않음). `wolf`는 id를 다시 썼지만 **운동 → 명상(파도 늑대)**으로 옮겼다.
- 모든 카테고리에 Lv.1 종이 있어서 "탐색했는데 만날 몬스터가 아예 없음"(emptyPool)은 이제 실제로는 나오지 않는다. 코드는 남겨 둔다 (서버가 빈 목록을 줄 수도 있음).
