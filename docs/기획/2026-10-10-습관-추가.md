# 홈에서 습관 추가하기

- 날짜: 2026-10-10
- 상태: 구현 완료 (2026-10-10, 아직 커밋 전)
- 관련: 온보딩 2단계(습관 등록)의 단계형 폼 (`features/onboarding/step_habits.dart`)

## 1. 왜 만드나
- **문제**: 습관은 온보딩에서 한 번만 등록할 수 있다. 홈에 들어온 뒤에는 새 습관을 더할 방법이 없다.
- **목표**: 쓰는 도중에도 홈에서 바로 습관을 추가할 수 있다.
- **하지 않는 것**: 습관 수정(이름 · 목표 바꾸기). 그만두기(삭제)는 넣기로 했다 (10-10 결정).

## 2. 누가 · 언제 쓰나
- 사용자: 이미 온보딩을 끝내고 쓰고 있는 사람.
- 상황: 새로 시작하고 싶은 습관이 생겼을 때, 홈에서.
- 사용 흐름:
  1. 홈 오른쪽 위 아이콘 줄(상점 · 가방 · 출석) 맨 아래의 **습관 추가** 아이콘을 누른다.
  2. 온보딩과 같은 순서로 입력한다: 무엇을(카테고리 · 이름 · 추천 습관) → 얼마나(측정 방식 · 하루 목표) → 언제까지(기간).
  3. "등록"을 누르면 창이 닫히고 "새 습관을 등록했어요" 알림이 뜬다. 아래 시트의 습관 리스트에 바로 보인다.

## 3. 규칙
- 습관은 최대 5개까지다 (`Economy.maxActiveHabits`). 이미 5개면 "내 습관" 화면에 추가 폼 대신 "최대 5개까지예요. 새로 넣으려면 하나를 그만두세요" 안내가 보인다.
- 카테고리는 **지금 열려 있는 카테고리**에서만 고를 수 있다. (DB 규칙: 열지 않은 카테고리에는 습관을 만들 수 없다)
- 이름이 비어 있거나 하루 목표가 0이면 등록할 수 없다. (온보딩과 같은 검사)
- [가정] 같은 이름의 습관도 등록할 수 있다 (온보딩이 막지 않으므로 같게 둔다).
- [가정] **오늘 이미 체크인을 확정한 뒤에 추가한 습관**은 오늘 보상에 들어가지 않는다. 챗봇의 "다시 체크"에서는 물어보지만 기록만 남고, 다음 날부터 정상 반영된다. (보상은 첫 확정 기준이라는 기존 규칙과 같다)
- [가정] 아직 오늘 체크인 전이면, 새 습관도 오늘 챗봇이 묻는다.
- 추가한 습관의 시작일은 오늘이다. 기간(7일 · 30일 · 100일)은 등록할 때 고른다.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 습관 최대 개수 | 5 | 기존 `Economy.maxActiveHabits` (DB `max_active_habits`와 같음) |

## 4. 화면
- 디자인 시안에 없는 추가 기능이다.
- 아이콘: 출석 아래 네 번째. [가정] 연필이 그려진 두루마리(퀘스트 추가) 모양, 이름표는 "습관".
- 입력 창: 처음엔 온보딩 2단계의 폼을 그대로 썼는데 **가독성이 나빠서 새로 그렸다** (10-10). 홈과 같은 어두운 테마, 목록 화면과 추가 화면을 분리, 한 화면에 질문 하나("어떤 습관을 시작할까요?" → "하루에 얼마나 할까요?" → "언제까지 해 볼까요?"), 글자 12~19px · 누르는 칸 48px 이상. 입력 상태와 검사 로직은 온보딩과 같은 `OnboardingController`를 쓴다.
- 튜토리얼 6번째 장면("상점 · 가방 · 출석")의 문구에 습관 추가를 넣는다.

## 5. 예외 · 경계
- 습관이 5개일 때: 화면은 열리고(그만두기는 할 수 있어야 하므로) 추가 폼만 안내로 바뀐다.
- 습관이 1개일 때: 그만두기를 누르면 "습관은 1개 이상 있어야 해요" 알림만 뜬다.
- 열린 카테고리가 1개뿐일 때: 카테고리 선택이 하나만 보인다.
- 좁은 화면(360×640): 아이콘이 4개가 되면 아이콘 줄이 길어져 몬스터와 겹칠 수 있다 → 구현할 때 캡처로 확인하고, 겹치면 아이콘 간격을 줄인다.
- 입력 중 창을 닫으면 입력한 내용은 버린다 (확인 창 없음) — [가정].
- 서버를 붙였을 때: `POST /habits`. 개수 제한과 카테고리 검사는 서버 · DB가 다시 한다.

## 6. 다른 곳에 미치는 영향
- 앱: `HomeScreen`(아이콘), `GameState.addHabit`(새 메서드), 온보딩 폼을 홈에서도 쓰도록 분리, `MainShell`(튜토리얼 문구), 기존 테스트의 아이콘 수.
- 서버 · DB: 없음 (지금은 로컬). API 초안에 `/habits`가 이미 있다.
- 문서: `프로젝트-이해.md` 4장(화면), 흐름도(홈에서 습관 추가), `기획-변경-이력.md`.

## 7. 완료 기준
- [ ] 홈의 습관 아이콘으로 습관을 추가하면 습관 리스트와 챗봇 질문에 나타난다
- [ ] 5개일 때는 추가되지 않고 알림이 뜬다
- [ ] 체크인 확정 뒤 추가한 습관은 오늘 골드 · 성실도에 영향을 주지 않는다
- [ ] `flutter analyze` 이상 없음, `flutter test` 전부 통과
- [ ] 화면을 눈으로 확인 (390폭 · 360폭)
- [ ] `작업-기록.md` · `기획-변경-이력.md` · `프로젝트-이해.md` · 흐름도 갱신

## 8. 정해야 할 것
- [x] 추가만 넣을지, 그만두기도 넣을지 → **그만두기도 넣는다** (10-10)
- [x] 아이콘 이름표 → **"습관"** (10-10)
- [ ] 위 [가정] 표시한 항목들 — 따로 반대가 없어 가정대로 구현했다. 바꾸고 싶으면 말하기
- [ ] 그만둔 습관을 되살리는 기능이 필요한지 (지금은 되돌릴 수 없다)

## 9. 결과
- 기획과 달라진 점
  - 아이콘을 누르면 추가 폼만 뜨는 게 아니라 **"내 습관" 화면**이 뜬다: 지금 습관 목록(줄마다 그만두기 ✕) + 추가 폼. 5개면 폼 대신 안내가 보인다 (창이 안 열리는 대신).
  - 그만두기 규칙을 새로 정했다: **마지막 1개는 그만둘 수 없다**(체크할 습관이 없으면 흐름이 끊김), 그만두기 전에 확인 창, **이미 받은 골드 · 카테고리 경험치 · 오늘의 성실도는 그대로**, 되돌릴 수 없다.
  - 챗봇이 질문하던 중에 습관 목록이 바뀌면 처음부터 다시 묻는다.
  - 화면을 다시 디자인했다: 온보딩 부품을 그대로 가져온 첫 버전은 글자가 작고(9.5px) 목록과 폼이 한 화면에 몰려 읽기 어려웠다. 목록("내 습관": 카드 · 정보 칩 · 그만두기 · 빈 자리) ↔ 추가(3단계, 아래 고정 버튼)로 나눴다.
- 확인한 것: `flutter analyze` 이상 없음, 테스트 79개 통과(새 테스트 6개), 390 · 360폭 화면 캡처 확인.
- 확인하지 못한 것: 에뮬레이터에서 직접 눌러 보기. 360폭에서 몬스터가 오른쪽 끝으로 걸어가면 아이콘과 살짝 겹칠 수 있다 (아이콘 3개일 때도 있던 문제).
- 다음에 할 일: 습관 수정, 그만둔 습관 되살리기 여부 결정.
