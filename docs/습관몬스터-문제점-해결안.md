# 습관 몬스터 앱 — 문제점 및 해결안

원본 기획서의 확정 내용을 기준으로, 구현 및 운영 과정에서 발생할 수 있는 문제와 권장 해결책을 정리한 문서다. 원본 기획서에서 `[미결정]`으로 표시된 항목 자체는 평가 대상에서 제외했다.

## 1. 기록 수치 최적화 문제

### 문제

정량 습관의 경험치가 `오늘 기록값 ÷ 최근 14일 평균`으로 계산되기 때문에, 사용자가 습관을 잘 수행하는 것보다 기록값을 유리하게 만드는 데 집중할 수 있다. 초기에 낮은 값을 입력하거나 측정 단위를 바꾸는 방식의 조작도 가능하다.

### 해결안

- 카테고리별 추천 측정 단위를 기본값으로 제공한다.
- 초기 3~5회는 보상 계산이 아니라 기준값을 만드는 기간으로 사용한다.
- 평균 대신 최근 기록의 중앙값을 사용하는 방안을 검토한다.
- 기록값에 현실적인 일일 상한을 둔다.
- 보상 구간과 계산 기준을 사용자에게 미리 공개한다.

### 권장 MVP안

- 체크인 기본 보상: 10
- 수행 보너스: 3 / 10 / 15의 세 구간
- 하루 최대 경험치: 25
- 최근 기록 중 비정상적으로 큰 값은 자동으로 확인 요청

## 2. 자가진단과 정량 측정의 신뢰도 차이

### 문제

자가진단 1~5점은 사용자의 주관적 입력에 전적으로 의존한다. 정량 측정과 보상 범위만 같게 맞추면 실제 난이도와 데이터 신뢰도가 같다고 오해할 수 있다.

### 해결안

- 자가진단은 주관적 기록 방식임을 화면에 명시한다.
- 점수 입력 시 짧은 보조 질문을 제공한다.
- 동일한 고득점이 장기간 반복될 때 추가 보너스가 계속 쌓이지 않도록 한다.
- 자가진단과 정량 측정의 정확도가 다르다는 점을 사용자에게 설명한다.

### 예시 질문

- 계획한 행동 중 몇 회를 수행했나요?
- 실제로 수행한 시간을 입력할 수 있나요?
- 오늘 수행한 행동을 한 문장으로 설명할 수 있나요?

## 3. 버튼만 누르는 체크인 문제

### 문제

체크인 버튼만 누르면 실제 습관 수행 여부를 확인하기 어렵다. 단순히 매일 버튼만 누르는 사용자도 정상적으로 습관을 수행한 사용자와 비슷한 성장을 할 수 있다.

### 해결안

- 체크인 후 실제 수행량 또는 수행 내용을 한 번 더 입력하게 한다.
- 과거 기록의 임의 수정은 제한하고 수정 내역을 남긴다.
- 비정상적으로 반복되는 기록에는 확인 절차를 제공한다.
- GPS, 센서, 사진 인증 등은 필수가 아닌 선택 기능으로 둔다.

## 4. AI 보정의 불투명성

### 문제

AI가 경험치를 최대 20% 보정하면 사용자는 보정 이유를 이해하지 못할 수 있다. 자유 대화의 오해석, 농담이나 과장 표현에 대한 오판, 생활정보 처리 문제도 발생할 수 있다.

### 해결안

- 기본 보상은 규칙 기반으로만 계산한다.
- AI는 기록 요약, 격려, 이상값 알림을 우선 담당한다.
- AI 보정 전 사용자 확인을 받는다.
- 보정 이유와 적용 수치를 표시한다.
- 사용자가 잘못된 판단을 신고하거나 기록을 수정할 수 있게 한다.

### 권장 MVP안

MVP에서는 AI가 경험치에 직접 개입하지 않고, 이상 기록을 알려주는 보조 기능으로만 사용한다.

## 5. 미접속 페널티와 복귀 장벽

### 문제

단기 미접속 시 능력치가 하락하면 사용자가 손실감을 느낄 수 있다. 하루나 이틀의 실패가 “이미 늦었다”는 인식으로 이어져 앱을 완전히 포기하게 만들 가능성이 있다.

### 해결안

- 미접속 시 도감, 몬스터 레벨, 누적 성장을 감소시키지 않는다.
- 스트릭만 종료하고 기존 성과는 보존한다.
- 복귀 시 작은 복귀 보너스를 제공한다.
- 장기 미접속자는 동결 후 기존 수치 그대로 재개한다.
- 실패한 날짜를 무제한으로 한 번에 보충하는 기능은 제공하지 않는다.

### 권장 MVP안

- 1~2일 미접속: 페널티 없음
- 3일 이상 미접속: 스트릭 종료
- 성장 수치와 수집 결과: 유지
- 복귀 시 1회성 복귀 보너스 제공

## 6. 투두 보상 악용 및 인플레이션

### 문제

사용자가 직접 투두를 만들기 때문에 매우 쉬운 목표를 등록하고 반복해서 아이템을 얻을 수 있다. 최대 개수 제한만으로는 목표 난이도와 보상량을 통제하기 어렵다.

### 해결안

- 일일 아이템 보상에 상한을 둔다.
- 동일하거나 지나치게 짧은 목표의 반복 생성을 제한한다.
- 목표 난이도를 쉬움·보통·어려움으로 선택하게 한다.
- 완료 보상은 목표 개수뿐 아니라 난이도에 따라 차등 지급한다.
- 미래 날짜의 목표를 미리 완료할 수 없게 한다.
- 주간·월간 목표는 정해진 기간 동안 유지한다.

### 권장 MVP안

AI가 목표 난이도를 판정하기보다 사용자가 난이도를 선택하게 하고, 시스템은 하루 총 보상량만 제한한다.

## 7. 수집 축과 육성 축의 속도 차이

### 문제

카테고리 완성은 약 100일이 걸리는 반면, 몬스터 최종 진화는 약 2주 만에 가능하다. 대부분의 몬스터가 빠르게 최종형이 되면 투두 체크의 즉각적인 보상이 약해진다.

### 해결안

- 1차 진화는 빠르게 유지하되 최종 진화까지는 조금 더 긴 기간을 요구한다.
- 투두 보상에 일일 상한을 둔다.
- 최종 진화 이후에는 능력치 대신 꾸미기, 포즈, 배경, 전시 효과를 보상한다.
- 최종 진화 몬스터도 계속 사용할 수 있는 소비처를 마련한다.

### 권장 MVP안

최종 진화 이후의 성장은 수치 인플레이션보다 꾸미기와 도감 완성 보상 중심으로 설계한다.

## 8. 기간 배수 보너스의 과도한 성장

### 문제

장기간 달성 시 능력치를 배수로 일괄 지급하면 특정 시점에 지나치게 많은 보상이 몰릴 수 있다. 여러 기간 보너스의 중첩 여부와 적용 대상도 불명확하다.

### 해결안

- 전체 능력치에 배수를 곱하지 않고 해당 습관의 일부 보상에만 적용한다.
- 일괄 지급 대신 다음 몇 회의 체크인에 추가 보상을 나누어 지급한다.
- 중첩 여부, 실패 시 처리, 미접속 시 동결 여부를 규칙으로 명시한다.
- 기간 보너스가 전체 성장량의 일정 비율을 넘지 않도록 상한을 둔다.

### 권장 방식

- 1주 달성: 다음 체크인 보상 +20%
- 1개월 달성: 특별 아이템 1개
- 3개월 이상: 꾸미기 요소 또는 한정 도감 보상

## 9. 중복 제거 랜덤의 후반 단조로움

### 문제

중복을 제거하면 도감 완성은 보장되지만, 획득 가능한 종이 줄어들수록 사실상 정해진 순서대로 얻는 느낌이 강해진다. 마지막 종을 얻는 과정이 단순한 대기처럼 느껴질 수 있다.

### 해결안

- 랜덤 결과 대신 2~3개의 후보 중 하나를 선택하게 한다.
- 일부 몬스터는 특정 습관 유형이나 달성 조건과 연결한다.
- 마지막 몇 종은 선택권 또는 확정 교환으로 획득하게 한다.
- 희귀 몬스터는 낮은 확률보다 특별한 행동 조건으로 차별화한다.

## 10. 콘텐츠와 아트 규모 과대 산정

### 문제

140종 × 3형태는 420개의 이미지뿐 아니라 이름, 설명, 속성, 진화 연출, 애니메이션, 도감 데이터, UI 상태, 테스트까지 포함한다. AI를 활용하더라도 수정과 통합, 일관성 검수 비용이 발생한다.

### 해결안

- MVP는 카테고리 3개, 카테고리당 5~8종으로 제한한다.
- 모든 몬스터에 고유한 복잡한 연출을 붙이지 않는다.
- 공통 애니메이션과 UI 컴포넌트를 재사용한다.
- 몬스터를 코드 수정 없이 데이터 추가만으로 등록할 수 있게 설계한다.
- 신규 몬스터 추가를 고려해 도감과 진화 데이터를 분리한다.

## 권장 MVP 운영 원칙

현재 기획에 가장 적은 변경으로 적용할 수 있는 조합은 다음과 같다.

1. 보상 계산은 규칙 기반으로 처리한다.
2. 체크인과 실제 기록 입력을 분리한다.
3. 미접속 시 기존 성장 수치는 감소시키지 않는다.
4. 투두 보상에 일일 상한을 둔다.
5. 기간 보너스는 전체 능력치 배수가 아니라 추가 보상으로 지급한다.
6. 중복 제거 랜덤에 후보 선택권을 추가한다.
7. MVP 몬스터 수를 카테고리당 5~8종으로 줄인다.
8. 최종 진화 이후에는 꾸미기와 전시를 중심으로 보상한다.

이 조합은 습관 기록의 조작 가능성, 복귀 장벽, 보상 인플레이션, 콘텐츠 제작 부담을 동시에 줄이면서 원래의 “습관이 게임의 수단”이라는 방향을 유지한다.
