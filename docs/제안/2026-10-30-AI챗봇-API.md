## 1. POST /checkins/today/interpret — 대화 해석 (새로)

사용자가 챗봇에 쓴 말을 서버가 AI(Gemini)에 보내 해석하고, **검사를 통과한 기록 후보**와 몬스터의 대답을 돌려준다.
이 API는 **아무것도 확정하지 않는다.** 앱은 후보를 확인 카드로 보여 주고, 사용자가 [맞아]를 누르면 기존 `POST /checkins/today`로 제출한다.

```json
// 요청
{
  "businessDate": "2026-10-30",
  "message": "아침에 공원에서 30분 뛰었고 물은 2리터 마셨어",
  "history": [
    { "role": "BOT", "text": "오늘 아침 러닝은 했어?" }
  ],
  "draft": [
    { "habitId": 101, "done": true, "value": 45, "evidence": "VERIFIED" }
  ],
  "askingHabitId": 100
}
```

| 필드 | 설명 |
| --- | --- |
| `message` | 사용자가 쓴 말. 1 ~ 300자 |
| `history` | 직전 대화 최대 10개 (`BOT` · `USER`). 서버는 대화를 기억하지 않으므로 앱이 보낸다 |
| `draft` | 지금까지 정해진 후보 (다시 묻지 않게). 없으면 빈 배열 |
| `askingHabitId` | 챗봇이 방금 물어본 습관 (없으면 null) |

```json
// 응답 200
{
  "reply": "와, 공원에서 30분이나 뛰었구나! 물도 2L 다 마셨네~",
  "answers": [
    { "habitId": 100, "done": true, "value": 30, "evidence": "DETAILED", "confidence": 0.92 },
    { "habitId": 102, "done": true, "value": 2, "evidence": "SHORT", "confidence": 0.88 }
  ],
  "askAgain": null,
  "remainingHabitIds": [103],
  "safety": false,
  "source": "LLM"
}
```

| 필드 | 설명 |
| --- | --- |
| `reply` | 몬스터 말투의 대답 (최대 120자). 점수 · 골드 숫자는 넣지 않는다 |
| `answers` | 이번 말에서 해석한 기록 후보. `value`는 서버가 **그 습관의 선택지 중 가장 가까운 값**으로 맞춘 값(D-42), O·X는 `1` |
| `evidence` | `SHORT`(짧은 자기보고) · `DETAILED`(구체적 자기보고). **`VERIFIED`는 이 API가 붙이지 않는다** — 타이머 · 헬스 기록이 있을 때 제출 시 서버가 붙인다 |
| `confidence` | 0 ~ 1. 서버 기준(`ai_min_confidence`, 기본 0.6)보다 낮은 후보는 `answers`에서 빼고 `askAgain`으로 바꾼다 |
| `askAgain` | 다시 물어야 할 때 `{ "habitId": 100, "question": "몇 분쯤 했어?" }`. 같은 습관은 **한 번만** 다시 묻고, 그 뒤엔 `null` + 앱이 선택지 버튼을 보여 준다 |
| `remainingHabitIds` | 아직 기록 후보가 없는 오늘 대상 습관 (등록 순서) |
| `safety` | 힘든 감정 · 위기 신호를 감지하면 `true`. `reply`는 안내 문구로 바뀌고, 앱은 게임 연출(보상 칩 등)을 멈춘다 |
| `source` | `LLM` · `TEMPLATE`(AI 실패 · 3초 초과 · 형식 오류 → 해석 없이 대본형 질문) |

**서버가 AI 답을 믿지 않고 다시 검사하는 것**
1. `habitId`가 오늘 체크인 대상인지 (아니면 버린다)
2. `value`가 측정 항목의 0 ~ `max_value` 안인지 (밖이면 버리고 `askAgain`)
3. 선택지에 맞추기 (가장 가까운 값), O·X는 0/1만
4. AI가 낸 다른 필드(점수 · 골드 등)는 무시한다 — 응답 형식에 그런 칸이 없다
5. 사용자의 말 속 지시("점수 25로 해", "프롬프트 무시해")는 해석 대상일 뿐, 따르지 않는다 (프롬프트 원문: `docs/AI-프롬프트.md`)

| 검사 | 실패 시 |
| --- | --- |
| `businessDate`가 서버 오늘과 다름 | 409 `BUSINESS_DATE_CHANGED` |
| 오늘 체크인 대상 습관이 없음 | 409 `NO_ACTIVE_HABIT` |
| `message`가 비었거나 300자 초과, `history` 10개 초과 | 400 `INVALID_REQUEST` |
| 하루 AI 호출 한도(`ai_daily_call_limit`, 기본 60) 초과 | 429 `AI_RATE_LIMITED` — 앱은 버튼(대본형)으로 이어 간다 |
| AI 실패 · 3초 초과 | 오류가 아니라 200 + `source: "TEMPLATE"`, `answers: []` |

- 이미 오늘 제출했어도 부를 수 있다 (다시 체크 대화). 보상은 첫 제출 기준 그대로다.
- 대화 원문은 DB에 남기면 보관 기간(`chat_message_retention_days`) 뒤 삭제한다 (DB 제안 1).

## 2. 체크인 제출 · 수정 — `evidence` 추가 (바뀜)

`POST /checkins/today` · `PUT /checkins/today`의 `answers` 각 항목에 선택 필드 `evidence`를 더한다.

```json
// 요청 (추가된 필드만)
{ "habitId": 100, "done": true, "value": 30, "evidence": "DETAILED" }
```

- 보낼 수 있는 값: `SHORT` · `DETAILED`. 없으면 `SHORT` (지금 버튼 체크와 같다). `VERIFIED`를 보내면 400.
- **서버가 근거를 정한다**: 그 습관 · 그날의 타이머(또는 헬스) 기록 합계가 제출 값 이상이면 `VERIFIED`.
- **점수 상한**: 4-1 공식으로 계산한 뒤
  - `SHORT` · `DETAILED` → 최대 `self_report_max_score`(기본 20). 목표를 넘긴 몫(21 ~ 25)은 못 받는다.
  - `VERIFIED` → 최대 25 (지금과 같다).
- **카테고리 경험치 계수**: 반영 습관의 경험치 = 점수 × 측정 방식 계수 × (확인됨이면 `exp_coef_verified`). 소수는 반올림. **골드는 그대로 1점 = 1G.**

| 측정 방식 | 설정 키 | 기본값 [가정] |
| --- | --- | --- |
| 시간 · 양 (`TARGET_RATIO`) | `exp_coef_ratio` | 1.0 |
| 범위 (`RANGE`, 수면) | `exp_coef_range` | 0.9 |
| O·X (`BINARY`) | `exp_coef_binary` | 0.8 |
| 확인된 기록 (곱하기) | `exp_coef_verified` | 1.2 |

```json
// 응답의 habits (추가된 필드)
{ "habitId": 100, "score": 20, "counted": true, "evidence": "DETAILED", "scoreCapped": true, "expGained": 20 }
```

- `scoreCapped`: 공식 점수가 상한에 걸려 깎였으면 `true` (앱이 "타이머로 재면 25점까지!" 안내).
- `categoryExp[].expGained`는 계수를 곱한 값이 된다.
- 다시 체크(PUT)는 지금처럼 최신 점수 · 근거만 바꾸고 보상은 첫 제출 그대로.

## 3. GET /checkins/today — 타이머 합계 (바뀜)

`tabs[].habits[]`에 `timerMinutes`(오늘 공부 타이머 합계, 정수 분, 없으면 0)를 더한다. 챗봇이 "타이머로 45분 했네! 이대로 적을까?"로 미리 채울 때 쓴다.

## 4. 공부 타이머 (새로)

시작 · 끝 시각은 **서버 시각**으로 기록한다 (앱 시계를 바꿔도 소용없게). 공부 카테고리(`st`)의 시간 측정 습관(`unit = 분`)에만 쓸 수 있다.

### POST /study-timers — 시작
```json
// 요청
{ "businessDate": "2026-10-30", "habitId": 101 }
// 응답 201
{ "timerId": 9, "habitId": 101, "status": "RUNNING", "startedAt": "2026-10-30T19:02:11+09:00", "elapsedSeconds": 0 }
```

### PATCH /study-timers/{timerId} — 일시정지 · 이어서 · 끝내기
```json
// 요청
{ "action": "PAUSE" }     // PAUSE | RESUME | STOP
// 응답 200
{ "timerId": 9, "status": "PAUSED", "elapsedSeconds": 1520, "todayMinutes": 25 }
```

### GET /study-timers/today
```json
{
  "running": { "timerId": 9, "habitId": 101, "status": "RUNNING", "elapsedSeconds": 1520 },
  "habits": [ { "habitId": 101, "todayMinutes": 70, "sessions": 3 } ]
}
```

**규칙**
- 한 사용자에 도는(RUNNING · PAUSED) 타이머는 하나뿐.
- 경과 시간 = 끝(또는 지금) − 시작 − 일시정지한 시간. 분은 내림.
- 한 번에 최대 `study_timer_max_minutes`(기본 240분). 넘으면 서버가 240분에서 자동으로 끝낸 것으로 본다 (켜 두고 자는 것 방지). 앱은 "아직 공부 중이야?"를 띄운다.
- 자정을 넘기면 00시까지는 시작한 날, 그 뒤는 다음 날 기록으로 나눈다.
- 1분 미만은 기록하지 않는다.
- 체크인 제출 뒤에 잰 시간은 그날 "다시 체크"로만 반영된다 (보상은 첫 제출 기준).

| 검사 | 실패 시 |
| --- | --- |
| 본인 습관이 아님 · 없는 타이머 | 404 |
| 공부 카테고리 시간 습관이 아님 | 422 `NOT_TIMER_HABIT` |
| 이미 도는 타이머가 있음 | 409 `TIMER_ALREADY_RUNNING` (응답에 그 `timerId`) |
| 끝난 타이머에 PAUSE · RESUME · STOP | 409 `TIMER_NOT_RUNNING` |
| 시작 때 `businessDate`가 오늘과 다름 | 409 `BUSINESS_DATE_CHANGED` |

## 5. POST /health-records — 운동 기록 올리기 (다음 단계)

안드로이드 Health Connect에서 읽은 오늘 운동 기록을 올린다. 아이폰은 출시 뒤 확장.
```json
// 요청
{ "businessDate": "2026-10-30", "exerciseMinutes": 32, "exerciseSessions": 1, "steps": 6540, "sourceApp": "com.sec.android.app.shealth" }
// 응답 200
{ "businessDate": "2026-10-30", "exerciseMinutes": 32, "exerciseSessions": 1, "steps": 6540 }
```
- 같은 날 다시 올리면 덮어쓴다 (가장 최근 값).
- 앱이 읽어 보낸 값이라 완전한 검증은 아니다 — 범위(분 0 ~ 600, 걸음 0 ~ 100,000)만 검사한다.
- 운동 카테고리(`ex`)의 "운동 시간(분)" 습관은 `exerciseMinutes`, "운동 횟수(회)"는 `exerciseSessions`가 제출 값 이상이면 `VERIFIED`.

## 6. 새 오류 코드

| 코드 | 상태 | 메시지 (화면 그대로) |
| --- | --- | --- |
| `AI_RATE_LIMITED` | 429 | 오늘은 대화를 많이 했어요. 버튼으로 이어서 체크해요. |
| `NOT_TIMER_HABIT` | 422 | 공부 시간 습관에서만 타이머를 쓸 수 있어요. |
| `TIMER_ALREADY_RUNNING` | 409 | 이미 재고 있는 타이머가 있어요. |
| `TIMER_NOT_RUNNING` | 409 | 이미 끝난 타이머예요. |
