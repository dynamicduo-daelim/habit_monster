## 1. 규칙
- 그달 퀘스트 **완료 20개** → 그달 배지 + 성실볼 1개 선물. **한 달에 한 번**.
- 일일 · 주간 (다음 단계에서 깜짝 · 조건 깜짝)을 **1개씩**. 점수 합이 아니라 개수. 선물을 **받았는지와 무관**하게 완료로 센다.
- **완료한 날의 달**로 센다 — 10월 27일 주의 주간 퀘스트를 11월 2일에 완료하면 11월 1개.
- 배지 보관함은 **받은 달만** (놓친 달은 빈칸으로도 안 보임 — 기획 4-3, 실패 비처벌).

## 2. 카운터 동작
```
퀘스트 완료 (completeIfReached — 지갑을 이미 잠근 뒤)
  ├ user_quest → DONE (지금과 같음) → 선물 (지금과 같음)
  └ user_month 이번 달 줄:
      없으면 → 만들면서 시작값 = 그달 이미 DONE인 user_quest 수 (방금 것 포함)
      있으면 → completed_count + 1
      (한 문장: INSERT … SELECT count(*) … ON CONFLICT DO UPDATE SET completed_count = completed_count + 1)
    → completed_count ≥ 목표이고 배지 시각이 비어 있으면 조건부로 채움 (한 번만 성공)
       → 성공했으면 성실볼 선물 (출처 QUEST_MONTHLY, 출처 번호 = user_month.id, 제목 "2026년 11월 배지")
```
- **시작값을 기록에서 채우는 이유**: 이 기능이 배포되기 전(11월 1일 ~)에 완료한 퀘스트도 세려고. Supabase의 옛 방식 4건(11-25 ~ 26)도 들어간다. 그다음부터는 +1만.
- **두 번 세지 않는 이유**: 줄을 만드는 순간의 시작값이 방금 완료한 것까지 포함하고, 그때는 +1을 하지 않는다 (INSERT 쪽). 이미 있으면 +1만 (UPDATE 쪽). 같은 사용자의 퀘스트 처리는 항상 지갑 행을 먼저 잠가(D-87) 줄을 서므로, 두 요청이 동시에 와도 한 줄 · 정확한 수.
- **조회 때도**: `GET /quests`가 이번 달 줄을 만들고(+1 없이 — 시작값만) 배지 조건을 본다. 줄이 없는 달에 이미 20개를 넘긴 경우(배포 전 완료)에 배지가 빠지지 않게.
- 잠금 순서 그대로: `… → wallet → quest(user_quest · user_month) → gift(새 행)`.
- `quest_enabled`가 false면 완료가 없으니 세지도 않고, `monthly`는 응답에 없다.

## 3. API 명세 (v10 → v11)
### `GET /quests` — 칸 추가
```json
  "monthly": { "monthStart": "2026-11-01", "completed": 7, "target": 20, "badgeEarned": false }
```
- `completed`는 목표를 넘어도 계속 센다 (예: 23). 진행바는 앱이 `min(completed, target)`으로.
- `quest_enabled` false면 `"monthly": null`.

### `GET /quests/badges` — 새로 (배지 보관함)
```json
// 응답 200
{ "badges": [ { "month": "2026-11", "earnedAt": "2026-11-20T21:03:00+09:00" } ] }
```
- **받은 달만**, 최신순. 없으면 `"badges": []`.
- 배지 그림은 앱이 `month`로 고른다 (월마다 그림을 바꿀지는 앱 · 아트 담당).

### 10장 설명 추가
- 월간 배지 규칙(1장) · 성실볼은 선물함 `source: "QUEST_MONTHLY"` (`gold` 0, `itemCode: "BALL"`, `quantity: 1`).
- 한눈에 보기 51개 → **52개**.

## 4. DB (v1.13 → v1.14)
```sql
CREATE TABLE quest.user_month (
  id               BIGINT       GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id          BIGINT       NOT NULL REFERENCES identity.users(id),
  month_start      DATE         NOT NULL CHECK (extract(day FROM month_start) = 1),  -- 그달 1일
  completed_count  SMALLINT     NOT NULL DEFAULT 0 CHECK (completed_count >= 0),
  badge_earned_at  TIMESTAMPTZ  NULL,                                                 -- NULL = 아직 배지 없음
  CONSTRAINT uq_user_month UNIQUE (user_id, month_start)
);
-- 트리거: badge_earned_at은 NULL → 값 한 번만 (되돌리기 · 다시 쓰기 금지)

INSERT INTO gift.gift_source (code, description) VALUES ('QUEST_MONTHLY','월간 배지 (성실볼)');
-- 설정
('quest_monthly_target',      '20', '월간 배지: 그달 퀘스트 완료 N개 (v1.14)'),
('quest_monthly_ball_reward', '1',  '월간 배지 보상 성실볼 개수 — 선물함으로 (v1.14)'),
```
- 원장 사유는 추가하지 않는다 — 볼만 주는 선물이라 골드가 없다 (verify S-33은 골드 있는 선물만 검사).
- `verify.sql`: 같은 달 1줄 · 1일만 · 음수 불가 · 배지 시각 되돌리기 금지 · 설정 2개 · 출처 시드 · S-1 FK 24쌍(+ `quest.user_month` → `identity.users`) · `verify_later` L-A5 29쌍.
- `backend/db/migrate-v1.14.sql`: 테이블 · 트리거 · 출처 · 설정 (`IF NOT EXISTS` · `ON CONFLICT DO NOTHING`). **기존 데이터는 바꾸지 않는다** — 이번 달 줄은 서버가 처음 쓸 때 만든다. Supabase에서 돌리기 전 확인 쿼리(이번 달 완료한 퀘스트 수)를 따로 드린다. 서버는 새 설정 키가 없으면 뜨지 않으므로 **SQL이 배포보다 먼저**.
