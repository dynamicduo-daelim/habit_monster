## 1. 무엇을 · 왜
홈 필드에서 몬스터를 끌어 옮기면(DRAG) 몬스터마다 하루 1번 호감도 +1. 앱 시연 모드에서는 이미 되고, 서버 모드에서만 저장할 곳이 없어 꺼 두었다(D-46).
퀘스트 "번쩍 들어올리기"와 업적 "끌어 옮기기 누적"도 이 기록을 쓴다.

## 2. API 명세 (v6 → 다음 판)

### `POST /monsters/{id}/affection`
```json
// 요청
{ "action": "DRAG" }   // PET 쓰다듬기 | PLAY 놀아주기 | DRAG 필드에서 끌어 옮기기
// 응답 200
{ "gain": 1, "affection": 31, "affectionTier": "MID" }
```
- **DRAG만 예외**: 오늘 이 몬스터를 이미 끌었으면 409가 아니라 **200 `{ "gain": 0, … }`** (지금 호감도 그대로). 끌기는 홈에서 자주 일어나는 평범한 동작이라 오류가 아니다 (D-86).
- PET · PLAY는 지금처럼 409 `ALREADY_DONE_TODAY`.
- 호감도가 최대면 `gain` 0 (지금과 같음).

### `GET /monsters/{id}`
```json
"todayActions": { "pet": true, "play": false, "drag": false }
```

### 덧붙여 (윤서 파일이라 안 고침)
- 이 절의 예시(`affectionMax: 10`, `gain 2 / affection 8`)는 0~100 이전 값 — 다음 판에서 같이 고치면 좋다 (11-16 제안서에도 적힘).

## 3. DB

### 스키마 (`schema.sql`, v1.9 → v1.10)
```sql
CREATE TABLE monster.affection_action (
  ...
  action_type      TEXT         NOT NULL CHECK (action_type IN ('PET','PLAY','DRAG')),
  ...
  PRIMARY KEY (user_monster_id, action_date, action_type)    -- 하루 1회 (BR-59) — DRAG도 그대로 막힘
);
```
- **간식(`FEED`, D-79)과 겹침**: 간식도 같은 CHECK에 `'FEED'`를 더하는 안이 미뤄져 있다(11-16 제안서 · `verify.sql`). 간식을 같은 판에 넣을지 정해 주시면 CHECK를 `('PET','PLAY','DRAG','FEED')`로 한 번에 바꾼다.

### 시드 (`seed.sql`, `config.balance_config`)
```sql
('affection_drag_gain',        '1',          '필드에서 끌어 옮기기 (몬스터마다 하루 1회)'),
```
- 서버는 필수 키가 하나라도 없으면 **뜨지 않는다**(`BalanceConfig.REQUIRED`). → 배포 순서: **DB에 키 먼저 → 서버 배포**.

### `verify.sql`에 더할 확인
- `affection_drag_gain` 키가 `1`
- DRAG 같은 몬스터 · 같은 날 두 번 INSERT → 기본 키 위반 (하루 1회)

### 이미 만든 DB용 `backend/db/migrate-v1.10.sql` (안 — 로컬 Docker · Supabase에 한 번, 두 번 실행해도 안전)
```sql
BEGIN;
ALTER TABLE monster.affection_action DROP CONSTRAINT IF EXISTS affection_action_action_type_check;
ALTER TABLE monster.affection_action ADD  CONSTRAINT affection_action_action_type_check
  CHECK (action_type IN ('PET','PLAY','DRAG'));
INSERT INTO config.balance_config (key, value, description)
VALUES ('affection_drag_gain', '1'::jsonb, '필드에서 끌어 옮기기 (몬스터마다 하루 1회)')
ON CONFLICT (key) DO NOTHING;
COMMIT;
```
- 제약 이름은 실행 전에 `\d monster.affection_action`(또는 Supabase 테이블 화면)으로 확인. 이름이 다르면 DROP이 아무것도 안 지우고 ADD에서 CHECK가 두 개가 되어, 옛 CHECK가 DRAG를 계속 막는다.
