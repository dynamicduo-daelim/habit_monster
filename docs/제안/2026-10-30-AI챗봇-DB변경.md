## 1. `ai.chat_message` — 글 입력 허용 · 해석 결과

```sql
-- 사용자 글 입력: source에 'TEXT' 추가, USER는 WIDGET 또는 TEXT
ALTER TABLE ai.chat_message DROP CONSTRAINT ck_message_source;
ALTER TABLE ai.chat_message DROP CONSTRAINT chat_message_source_check;   -- 이름은 실제 제약 이름 확인
ALTER TABLE ai.chat_message
  ADD CONSTRAINT chat_message_source_check CHECK (source IN ('LLM','TEMPLATE','WIDGET','TEXT')),
  ADD CONSTRAINT ck_message_source CHECK (
    (role = 'USER' AND source IN ('WIDGET','TEXT')) OR
    (role = 'BOT'  AND source IN ('LLM','TEMPLATE')));

-- AI가 이 말에서 뽑은 기록 후보 (BOT 메시지에만, 감사 · 디버깅용). 점수 · 골드는 들어가지 않는다
ALTER TABLE ai.chat_message ADD COLUMN interpretation JSONB NULL;
-- 예: {"answers":[{"habitId":100,"done":true,"value":30,"evidence":"DETAILED","confidence":0.92}],"askAgain":null}
```
- 원문 보관 기간 · 탈퇴 시 삭제는 지금 규칙 그대로 (`chat_message_retention_days`).
- 대화 원문을 남기지 않기로 하면 이 항목은 빼도 된다 (API 제안 7장).

## 2. `habit.habit_checkin` — 근거 · 점수 상한

```sql
ALTER TABLE habit.habit_checkin
  ADD COLUMN evidence TEXT NOT NULL DEFAULT 'SHORT'
    CHECK (evidence IN ('SHORT','DETAILED','VERIFIED')),            -- 최신 근거 (다시 체크하면 바뀜)
  ADD COLUMN rewarded_evidence TEXT NOT NULL DEFAULT 'SHORT'
    CHECK (rewarded_evidence IN ('SHORT','DETAILED','VERIFIED')),   -- 첫 확정 근거 (불변, rewarded_* 와 같이)
  ADD COLUMN score_capped BOOLEAN NOT NULL DEFAULT false;           -- 자기보고 상한에 걸려 깎였는지
```
- `rewarded_evidence`는 `rewarded_value` · `rewarded_score`처럼 **수정 금지 트리거** 대상에 넣는다.
- 기존 행은 기본값 `SHORT`로 채워져 지금 보상과 달라지지 않는다.
- 카테고리 경험치는 저장된 `rewarded_score`에 계수를 곱해 계산하므로 칸을 더 만들지 않는다 (계산 결과는 기존 경험치 칸에 들어감).

## 3. `habit.study_timer` (새) — 공부 타이머

```sql
CREATE TABLE habit.study_timer (
  id               BIGINT       GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id          BIGINT       NOT NULL REFERENCES identity.users(id),
  habit_id         BIGINT       NOT NULL REFERENCES habit.habit(id),
  business_date    DATE         NOT NULL,                    -- 시작한 업무 날짜 (자정 넘으면 서버가 나눠 새 행)
  status           TEXT         NOT NULL CHECK (status IN ('RUNNING','PAUSED','STOPPED')),
  started_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),      -- 서버 시각
  paused_at        TIMESTAMPTZ  NULL,                        -- 지금 일시정지 중이면 그 시각
  paused_seconds   INTEGER      NOT NULL DEFAULT 0 CHECK (paused_seconds >= 0),
  ended_at         TIMESTAMPTZ  NULL,
  counted_minutes  SMALLINT     NULL CHECK (counted_minutes BETWEEN 0 AND 240),  -- 끝낼 때 확정 (최대 study_timer_max_minutes)
  CONSTRAINT ck_timer_end CHECK ((status = 'STOPPED') = (ended_at IS NOT NULL))
);
-- 한 사용자에 도는 타이머는 하나
CREATE UNIQUE INDEX uq_study_timer_active ON habit.study_timer (user_id) WHERE status IN ('RUNNING','PAUSED');
CREATE INDEX ix_study_timer_day ON habit.study_timer (user_id, business_date);
```
- 오늘 합계 = `SUM(counted_minutes) WHERE user_id = ? AND habit_id = ? AND business_date = ? AND status = 'STOPPED'`.
- 공부 카테고리 · 시간 습관인지는 서버 규칙으로 검사 (스키마 간 검사가 복잡해서 CHECK로 두지 않음).
- 탈퇴 정리: habit 모듈의 `WithdrawalStep`에 추가.

## 4. `habit.health_daily` (새, 다음 단계) — 안드로이드 Health Connect

```sql
CREATE TABLE habit.health_daily (
  user_id            BIGINT       NOT NULL REFERENCES identity.users(id),
  business_date      DATE         NOT NULL,
  exercise_minutes   SMALLINT     NOT NULL DEFAULT 0 CHECK (exercise_minutes BETWEEN 0 AND 600),
  exercise_sessions  SMALLINT     NOT NULL DEFAULT 0 CHECK (exercise_sessions BETWEEN 0 AND 50),
  steps              INTEGER      NOT NULL DEFAULT 0 CHECK (steps BETWEEN 0 AND 100000),
  source_app         VARCHAR(100) NULL,                       -- 예: com.sec.android.app.shealth (삼성 헬스)
  updated_at         TIMESTAMPTZ  NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, business_date)                        -- 같은 날 다시 올리면 덮어씀
);
```
- 앱이 읽어 보낸 값이라 범위만 검사한다 (완전한 검증 아님 — 기획서 3-6 한계).
