## 1. 바로잡을 것 — 잠금 순서 (D-85 수정 제안)
D-85에서 "퀘스트는 지갑 **바로 앞**"(`… inventory → quest → wallet`)으로 정했는데, 코드를 보니 **지킬 수 없는 순서**다.
- 체크인은 골드를 줄 때 이미 지갑을 잠근다(`WalletService.credit` → `lockBalance`, 금액 0이어도). 체크인 이벤트를 받은 퀘스트는 그 **뒤에** 퀘스트 행을 건드린다 → 체크인 경로는 `wallet → quest`.
- 쓰다듬기는 지갑을 안 잠근 채 이벤트가 오고, 퀘스트가 완료되면 그제야 지갑을 잠근다 → `quest → wallet`.
- 같은 사용자의 두 요청이 동시에 오면 서로 상대가 쥔 것을 기다리는 **교착**이 생길 수 있다 (예: 같은 날 첫 조회에 퀘스트 행을 만드는 중).

**제안**: 순서를 **`… inventory → wallet → quest`** 로 바꾸고, 퀘스트 리스너 · `GET /quests`는 **항상 먼저 지갑 행을 잠근 뒤** 퀘스트 행을 다룬다. 그러면 모든 경로가 `wallet → quest` 한 방향이 된다.
- 대가: 골드를 안 주는 진행(+1)에도 지갑 행을 잠근다. 같은 사용자의 요청끼리만 줄을 서므로 영향은 작다.
- 지갑 모듈에 "잠그기만 하는" 메서드 하나 추가 (`WalletService.lock(userId)`).

## 2. API 명세 (v7 → v8)

### 새 절 "10. 퀘스트 (v8)" — `GET /quests`
```json
// 응답 200
{
  "businessDate": "2026-11-25",
  "enabled": true,
  "daily": [
    { "code": "DAILY_CHECKIN", "title": "오늘의 기록",        "progress": 1, "target": 1, "rewardGold": 3, "status": "DONE" },
    { "code": "DAILY_PET",     "title": "몬스터 쓰다듬기",    "progress": 0, "target": 1, "rewardGold": 1, "status": "IN_PROGRESS" },
    { "code": "DAILY_TIMER",   "title": "타이머 한 번 쓰기",  "progress": 0, "target": 1, "rewardGold": 1, "status": "LOCKED", "lockReason": "NO_TIMER_HABIT" },
    { "code": "DAILY_TALK",    "title": "몬스터에게 말 걸기", "progress": 0, "target": 1, "rewardGold": 1, "status": "IN_PROGRESS" }
  ]
}
```
- 그날 첫 조회 때 4개를 만든다 (스케줄러 없음, D-64). 행동이 먼저 오면 그때 만든다.
- `status`: `IN_PROGRESS` · `DONE` · `LOCKED`. **`LOCKED`는 저장하지 않고 조회 때 계산**한다 — 하루 중간에 시간 습관을 등록하면 바로 풀린다. `lockReason`은 `LOCKED`일 때만 (`NO_TIMER_HABIT` — 측정 단위가 "분"인 진행 중 습관이 없음).
- 완료 순간 서버가 골드를 자동 지급 (수령 버튼 없음). 잠긴 퀘스트는 진행도 지급도 없음.
- `quest_enabled`가 false면 `{ "businessDate", "enabled": false, "daily": [] }` — 진행 · 지급도 멈춤.
- 주간 · 깜짝 · 월간 칸은 3 · 4 · 6단계에서 같은 응답에 더한다.

### 판정 (명세 본문에 적을 것)
| 코드 | 언제 +1 | 아닌 것 |
| --- | --- | --- |
| `DAILY_CHECKIN` | 체크인 **첫 제출**(`POST /checkins/today`) — 결과 무관 | 다시 체크(`PUT`) |
| `DAILY_PET` | 쓰다듬기가 실제로 기록됐을 때 (몬스터마다 하루 첫 쓰다듬기, 호감도 최대여도) | 409로 거절된 쓰다듬기 |
| `DAILY_TIMER` | 타이머가 끝나 기록이 생겼을 때 (`STOPPED` — 사용자가 끝냄 · 최대 시간 · 습관 그만둠 모두, 분 무관) | 일시정지 · 이어서 |
| `DAILY_TALK` | `GET /monsters/{id}/line` 성공 | 404 |

## 3. DB (v1.10 → v1.11)

### 스키마
```sql
CREATE SCHEMA IF NOT EXISTS quest;   -- v1.11 퀘스트 (권한 반복문의 스키마 목록에도 'quest' 추가)

-- 퀘스트 마스터 (시드). 보상 · 목표 횟수는 여기 (상점 가격처럼 마스터 값)
CREATE TABLE quest.quest_def (
  code          TEXT         PRIMARY KEY,
  kind          TEXT         NOT NULL CHECK (kind IN ('DAILY','WEEKLY','SURPRISE','CONDITIONAL')),
  title         VARCHAR(40)  NOT NULL,
  target_count  SMALLINT     NOT NULL CHECK (target_count >= 1),
  reward_gold   INT          NOT NULL CHECK (reward_gold >= 0),
  sort_order    SMALLINT     NOT NULL,
  is_active     BOOLEAN      NOT NULL DEFAULT true    -- 지우지 않고 끈다 (원칙 7)
);

-- 사용자별 퀘스트 (기간마다 1행). 잠금(LOCKED)은 저장하지 않고 조회 때 계산
CREATE TABLE quest.user_quest (
  id            BIGINT       GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id       BIGINT       NOT NULL REFERENCES identity.users(id),
  period_start  DATE         NOT NULL,   -- 일일 = 그날, 주간 = 그 주 월요일, 월간 = 1일
  quest_code    TEXT         NOT NULL REFERENCES quest.quest_def(code),
  progress      SMALLINT     NOT NULL DEFAULT 0 CHECK (progress >= 0),
  target        SMALLINT     NOT NULL CHECK (target >= 1),      -- 만들 때 quest_def에서 고정
  reward_gold   INT          NOT NULL CHECK (reward_gold >= 0), -- 만들 때 고정 (마스터를 바꿔도 지난 퀘스트는 그대로)
  status        TEXT         NOT NULL DEFAULT 'IN_PROGRESS' CHECK (status IN ('IN_PROGRESS','DONE')),
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
  completed_at  TIMESTAMPTZ  NULL,
  CONSTRAINT uq_user_quest UNIQUE (user_id, period_start, quest_code),
  CONSTRAINT ck_user_quest_done     CHECK ((status = 'DONE') = (completed_at IS NOT NULL)),
  CONSTRAINT ck_user_quest_progress CHECK (progress <= target)
);
```
- 원칙 3-1 잠금 순서 주석: `… → shop.inventory → wallet.wallet → quest(user_quest 행)` (1장)
- 원장 사유 (열린 집합, INSERT 한 줄): `('QUEST_DAILY','CREDIT','일일 퀘스트 완료')` — `ref_id` = `user_quest.id`. 주간 · 깜짝 · 월간 · 업적 사유는 그 단계에서
- 탈퇴: `user_quest`는 지우지 않는다 (원칙 7 — 사용자 행이 남으므로 FK 그대로)
- `target_user_monster_id`(조건 깜짝의 대상 몬스터)는 7단계에서 열 추가
