# 제안: 퀘스트 보상을 선물함에서 받게 (수령형)

- 날짜: 2026-11-26 · 제안: 앱 쪽 (수연 · Claude) · 정할 사람: **윤서 (서버 · 명세 · DB 담당)**
- 관련: 앱 기획 `docs/기획/2026-11-26-선물함.md` · 명세 v9 10장 `GET /quests` · 스키마 v1.12 `quest.user_quest` · 결정 D-85 · D-87 · D-88
- 상태: **제안** — 명세 · 스키마 · 서버 코드는 아직 아무것도 바꾸지 않았다

## 1. 왜
- 사용자(수연) 요청: 홈에 **선물함**을 두고, 퀘스트 보상이 거기 **쌓였다가 [받기]** 로 들어오게.
- 지금 서버(v9)는 `progress`가 `target`에 닿는 순간 골드를 지갑에 넣는다(원장 `QUEST_DAILY` · `QUEST_WEEKLY`). 사용자는 퀘스트를 깬 순간을 알기 어렵고, 받는 손맛이 없다.
- 앱은 이미 선물함 화면을 만들었다 (feature/habit-tab). 시연 모드는 앱이 계산해 [받기]까지 되고, **서버 모드는 "자동 지급"으로만** 보인다. 이 제안이 들어가면 서버 모드도 같은 흐름이 된다.

## 2. 바꾸는 것 (안)

### 2-1. 완료와 지급을 나눈다
- 완료 순간에는 `status = 'DONE'`, `completed_at`만 남기고 **골드를 주지 않는다**.
- 받기 요청에서 지급: `claimed_at`을 채우고 지갑에 `reward_gold` 적립 (원장 사유 그대로 `QUEST_DAILY` · `QUEST_WEEKLY`, 참조 = `user_quest.id`로 중복 방지).

### 2-2. DB (v1.13 안)
```sql
ALTER TABLE quest.user_quest ADD COLUMN claimed_at TIMESTAMPTZ NULL;
ALTER TABLE quest.user_quest ADD CONSTRAINT ck_user_quest_claim
  CHECK (claimed_at IS NULL OR status = 'DONE');
-- 받을 선물 조회용
CREATE INDEX ix_user_quest_unclaimed ON quest.user_quest (user_id) WHERE status = 'DONE' AND claimed_at IS NULL;
```
- 기존 DONE 행(이미 지급된 것)은 마이그레이션에서 `claimed_at = completed_at`으로 채운다 → 두 번 지급되지 않음.

### 2-3. API (명세 v10 안)
- `GET /quests` — 각 칸에 `claimed`(bool) 추가, 응답 맨 위에 `unclaimedCount`(홈 배지용).
- **`GET /gifts`** — 받을 선물 목록: `[{ questId, code, title, rewardGold, periodStart, completedAt }]` (지난 날 · 지난 주 것도, 보관 기간 안이면).
- **`POST /gifts/{questId}/claim`** (`Idempotency-Key`) → `{ goldAwarded, gold }`. 이미 받았으면 200 `goldAwarded: 0` (D-86처럼 오류 대신).
- **`POST /gifts/claim-all`** (`Idempotency-Key`) → `{ goldAwarded, gold, claimed: n }`.
- `GET /me/status`에 `unclaimedGiftCount`를 넣으면 홈 배지를 따로 조회하지 않아도 된다 (선택).

### 2-4. 정할 것
- [ ] **보관 기간** — 안 받은 선물을 언제까지 남길지. 제안: 7일 (지나면 자동 지급 or 소멸 — 비처벌 원칙상 **자동 지급** 추천)
- [ ] 체크인 응답의 `gold`에 "오늘의 기록" 3G가 들어가던 것(v9) → 이제 빠진다. 앱은 받기 응답의 `gold`로 상단 바를 그린다
- [ ] 퀘스트 업적("완벽한 하루" 등)은 **완료** 기준인지 **받기** 기준인지 — 제안: 완료 기준 (받기를 늦게 해도 업적은 그날)

## 3. 앱이 할 일 (서버가 들어오면)
- `HttpGameRepository.loadQuests` — `autoPaid: false`, `claimable`을 `claimed == false && status == DONE`에서
- `claimQuestReward` — `POST /gifts/{questId}/claim`, 응답 `gold`를 상단 바에
- `GameState.pendingGiftCount` — 서버 값(`unclaimedCount`)으로
- 앱 화면은 그대로 (시연 모드와 같은 흐름)

## 4. 영향 · 위험
- 경제: 받지 않으면 골드가 늦게 들어올 뿐 총량은 같다 (보관 기간을 자동 지급으로 하면).
- 잠금 순서(D-87): 받기는 `quest → wallet` 순서로 잠근다 — 완료 알림 경로(지갑 → 퀘스트)와 달리 받기는 퀘스트 행을 먼저 잡아야 중복 지급을 막는다. 두 경로가 같은 사용자에서 동시에 돌면 교착 가능 → 받기도 **지갑 먼저**로 맞추는 게 안전 (확인 필요).
