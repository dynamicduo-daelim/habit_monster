## 1. 판정
| 코드 | 퀘스트 | 목표 | 계산 (이번 주 = 월요일 ~ 오늘) |
| --- | --- | --- | --- |
| `WEEKLY_ATTEND` | 주 4일 출석 | 4 | `habit.attendance`에 이번 주 출석한 날 수. **연속 필요 없음** (기획 1-4-B) |
| `WEEKLY_GOOD_DAYS` | 성실도 80% 이상인 날 2일 | 2 | 이번 주 각 날의 **첫 제출** 성실도(반영 습관의 첫 확정 점수 `rewarded_score`로 계산한 달성률 평균)가 `quest_weekly_rate_threshold`(80) 이상인 날 수. 다시 체크는 반영 안 됨 → 그래프(최신 값)와 다를 수 있다 (앱 안내 문구) |
| `WEEKLY_CATEGORIES` | 카테고리 3곳 체크인 | 3 | 이번 주 첫 제출에서 "했어"(`is_filled`)인 습관의 서로 다른 카테고리 수. **연 카테고리가 3개 미만이면 잠금** (자동 하향 없음 — 기획 4-2) |

- 진행도 = min(계산값, 목표), **내려가지 않는다** (`GREATEST`). 목표에 닿으면 그 순간 5G 지급 (원장 `QUEST_WEEKLY`, ref = `user_quest.id`).
- 잠긴 퀘스트는 계산 · 지급하지 않는다. 주 중간에 세 번째 카테고리를 열면 바로 풀리고, 그 주에 이미 체크인한 카테고리도 센다 (기록에서 계산하므로).
- 완료한 퀘스트는 잠그지 않는다 (2단계와 같음).

## 2. API 명세 (v8 → v9) — 10장 `GET /quests`에 칸 추가
```json
{
  "businessDate": "2026-11-25",
  "enabled": true,
  "daily": [ … ],
  "weekStart": "2026-11-24",
  "weekly": [
    { "code": "WEEKLY_ATTEND",     "title": "주 4일 출석",                 "progress": 2, "target": 4, "rewardGold": 5, "status": "IN_PROGRESS" },
    { "code": "WEEKLY_GOOD_DAYS",  "title": "성실도 80% 이상인 날 2일",     "progress": 1, "target": 2, "rewardGold": 5, "status": "IN_PROGRESS" },
    { "code": "WEEKLY_CATEGORIES", "title": "카테고리 3곳 체크인",          "progress": 0, "target": 3, "rewardGold": 5, "status": "LOCKED", "lockReason": "NOT_ENOUGH_CATEGORIES" }
  ]
}
```
- `weekStart` = 이번 주 월요일. 매주 월요일 00시에 새 3개.
- `lockReason` `NOT_ENOUGH_CATEGORIES` — 연 카테고리가 3개 미만. "N개 더 열면" 문구의 N은 앱이 계산한다 (앱이 연 카테고리를 안다).
- `quest_enabled` false면 `weekly`도 빈 목록.
- 판정 표 (1장)를 명세에 그대로.

## 3. DB (v1.11 → v1.12)
```sql
-- 원장 사유
('QUEST_WEEKLY','CREDIT','주간 퀘스트 완료'),        -- ref_id = quest.user_quest.id
-- 시드 quest.quest_def
('WEEKLY_ATTEND',     'WEEKLY','주 4일 출석',              4, 5, 11),
('WEEKLY_GOOD_DAYS',  'WEEKLY','성실도 80% 이상인 날 2일',  2, 5, 12),
('WEEKLY_CATEGORIES', 'WEEKLY','카테고리 3곳 체크인',       3, 5, 13),
-- 설정
('quest_weekly_rate_threshold', '80', '주간 퀘스트 "성실도 N% 이상인 날"의 N (v1.12)'),
```
- 목표 일수(4 · 2 · 3)는 `quest_def.target_count`, 기준 %(80)는 설정 키 — %는 퀘스트 마스터가 아니라 판정 규칙이라서.
- `user_quest.period_start` = 그 주 월요일 (스키마 주석에 이미 있음). 테이블 · 제약 변경 없음.
- `verify.sql`: 주간 시드 3개 · 보상 · 설정 키 · `QUEST_WEEKLY` 적립 (S-32).
- `backend/db/migrate-v1.12.sql` (`ON CONFLICT DO NOTHING`, 두 번 실행해도 안전). 새 서버 배포 전에.
